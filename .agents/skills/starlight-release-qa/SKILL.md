# 星芒 Release & QA

先读根目录 `AGENTS.md` 和当前任务的授权；通用保护不重复请求批准。所有路径相对仓库根目录。

## 开始与提交范围

- 记录分支/HEAD、完整 status、index 和工作区 diff、未跟踪文件，备份本轮会动的既有文件。按文件与增量分类：项目成果、必要测试、维护文档、未完成项、临时材料/用户数据。
- 核对本轮文件与验收版本的哈希/差异；审阅敏感值、私人绝对路径、实际数据库、模型、日志、安装包和备份。只在明确授权后逐文件暂存，检查完整 staged diff 与 `git diff --cached --check`。
- 用户授权提交哪些文件就只提交那些；混有历史修改且无法安全分离时停在可审查状态，不替用户做取舍。

## 按改动选验证

- 优先相关单元/Qt 测试、修改 Python 的编译、修改 JS 的 `node --check`、`git diff --check`。测试用外部临时目录和隔离设置，避免 pytest 默认 coverage 参数触碰 `.coverage`。
- 记录实际命令、退出码、passed/failed/skipped/warnings、测试源码版本。历史报告可以引用但必须标日期；没有对应哈希不能说“与验收版一致”。
- 确认基线失败和旧测试约定，不跳过或放宽断言制造全绿。首次失败/原生崩溃/挂起留证，诊断通过不能抹去首次失败；不无理由重复全套 CI。

## 有授权时的远端与发行

- 推送前查真实远端 SHA 和祖先关系，仅正常快进；不 force、不创建空提交刺激 CI，不改其他分支。仅在本次已有授权覆盖时临时排除失效代理，保持 SSL 校验，不改持久网络设置。
- CI 必须对准新 SHA，记录 Workflow 和 Windows Job 终态、测试范围和汇总。仅运行 tests/unit 的 CI 不能替 UI 背书；无日志就标未知。仅在明确授权、原工作流支持且确认无既有对应运行时，手动触发一次。
- 构建需独立授权。核查 `scripts/{build.ps1,build.spec,setup_full.iss}` 的显式来源、独立 staging、原生扩展/资源/许可证和私人配置排除；不覆盖旧 onedir/安装器。
- 冻结环境启动/import、真实联网、识别/播放、安装/卸载/数据保留分别验收。外部 Python 加入 `_internal` 的 import 不能当作冻结程序验证；记录最终 SHA-256/大小/路径和源码来源。无干净 Windows 环境就明确未验收。

## 收口

复查 index、剩余修改与历史文件保护；按实际证据更新 `docs/handoff/PRODUCT_ROADMAP.md` 和必要交接。给出文件清单、测试/CI/实机各自结论、风险与最少人工步骤；结束本轮，不自动开新功能或发布。
