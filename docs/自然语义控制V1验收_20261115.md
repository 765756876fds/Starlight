# 自研自然语义控制 V1：工程验收（2026-11-15）

## 范围与结论

基线为 `174d1684b456ecc70f314a51e6a0cb0a18049d5f`，分支 `a0-cleanup`。
本轮建立生产级有限组合语义、实时情境、安全执行守卫与独立本地交互记忆。
未接入 GGUF、Embedding 或 LLM；未更改 ASR、VAD、TTS、MPV 解码、音乐队列/随机算法、LoL、VPN 或安装器。
下述“通过”分别限定文本、替身、真实 SQLite、离屏 Qt 和静音 MPV；不代表真实麦克风、扬声器或在线平台已验收。

## 四层结构

1. `app/voice/natural_language.py`：有限动作词、评价词、对象词和语法组合，输出不可直接执行的 Meaning。
   先处理引用/转述、疑问、否定、主语、冲突和纠正作用范围；保留未解析残余时拒识，不用全文关键词猜测。
2. `natural_control.py` + 复用 `media_context.py`：实时读取两路 MPV，结合焦点、真实暂停对象、页面和可靠习惯选择领域。
   明确命令仍优先；新自然表达只映射既有或真实新增的业务适配器。执行前复核请求代次、内容身份和候选版本。
3. `interaction_memory.py`：有界 SQLite 账本和内存缓存。有限语义特征而非完整语音句子；弱反馈按原内容哈希归属，可单独撤销。
4. 原有 CommandBus / MusicController / MovieController：现有播放器与推荐服务负责业务；媒体工具经 QueuedConnection 交回 GUI。
   没有第二个播放器、语音队列或推荐选曲系统。业务结果继续与 TTS 结果分离，不因播报失败重执行业务。

## 实际接通的闭环

| 表达/语义 | 实际行为与边界 |
| --- | --- |
| 停一下、暂停会儿、接着放、恢复播放 | 按实时播放/暂停状态选择音乐或电影；双活跃无可靠焦点/习惯时澄清；无可控对象不执行 |
| 这歌没劲、不好听 | 冻结原歌曲身份，调用原下一首入口；仅已接受切换时提交原歌曲弱负反馈，不给新歌写错反馈 |
| 这首一般般 | 音乐下一首，反馈权重比负面评价更轻；普通“下一首”不产生负面偏好 |
| 这个不好看 | 确认当前影片，沿用原进度保存及停止流程；停止确认后才展示替代候选；不自动播放推荐 |
| 电影的一般评价 | 只提交轻微反馈，不自动停止电影 |
| 这首不错 | 写入既有明确喜欢，不自动加歌单 |
| 这首不错，给我留着 / 收藏这首 | 复用 music.db，在事务中创建/复用“我喜欢的音乐”；按本地 ID 或音源+歌曲 ID 去重；不清空其他歌单 |
| 换个感觉、换种口味、来点不一样的 | 复用换风格/换榜单能力；元数据不足时只换其他榜单，不虚构情绪标签；保留既有连续播放集合 |
| 找个好看的 | 优先当前影视类别/可靠历史；无法确定时混合电影、剧集、动漫候选；仅展示与搜索片源 |
| 接着看昨天的/上次未看完的 | 从真实续播记录筛选；唯一可靠对象走原续播，多对象供选择；没有昨天记录不猜测 |
| 第几部/选中候选 | 使用候选稳定 ID 和批次版本，复用搜索/续播；列表更新或服务取消后旧选择不再生效 |
| 歌词、队列、全屏、字幕等 | 复用已有窗口/控制能力；UI 工作在 GUI 线程，字幕使用真实媒体快照和原接口结果，不能仅返回接受就宣称完成 |
| 不是换歌，是换榜单 | 提取明确正向纠正，执行新要求；仅相邻、30 秒内且媒体代次可靠关联的原弱反馈可以撤销 |
| 我不是让你换歌 | 不切歌、不反向播放；只允许撤销能够可靠归属到刚才本次误判的弱反馈；其他动作否定不能撤销无关反馈 |
| 电影实际起播 | 观察到 MPV 非 idle 且非暂停后，通过现有音乐控制器暂停音乐；loadfile 接受或启动失败本身不打断音乐；停止电影不自动恢复音乐 |

持久歌单重命名、删除、清空指定歌单未新增模糊语音执行权；“清空歌单”不会再解释为清空临时队列。
“下一部电影”展示影视推荐，不误执行“下一集”；明确“下一集”保持旧行为。
影视收藏、没有可靠身份的模糊指代、未解析比喻和复杂多动作保留缺口/澄清，不注册空执行器。
少数旧明确命令仍沿用自己的领域契约，本轮不宣称所有历史命令都具有相同的情境推断范围。

## 私有记忆与学习

- 使用既有 USER_DATA_DIR：源码态项目 `data/interaction_memory.db`；安装态 `%LOCALAPPDATA%/Starlight/data/interaction_memory.db`。
- 不迁移或清空 music.db、music_preferences.db、影视历史/偏好；明确喜欢仍由原偏好库保存，固定歌单仍在 music.db。
- schema 1、幂等初始化；未来版本、损坏、目录不可写或锁超时关闭该记忆能力并给出普通用户提示，不改写原文件。
- 最多 2000 条；任务队列 64；最多一个按需 writer，空闲 0.5 秒退出。常规语音只排队和读取内存缓存，不等磁盘。
- observation 不算认可；同一次确认有稳定 ID 去重。至少两次明确纠正或三次独立确认才可在无其他可靠证据时帮助领域消歧。
- 当前学习粒度是有限动作/对象/评价特征，不是任意新词自动获得执行权。明确偏好优先，弱反馈有界，重启后仍能读取。
- 原内容键哈希，不保存原始录音、完整语音文本、播放 URL、账号或模型推理。
- 保存失败与喜欢成功分别反馈；记忆不可用不阻断已成功的播放。

## 冻结语料和误执行风险

第一套独立 70 条（34 正向、36 拒绝）在首次运行前冻结；初次语义严格 69/70。
遗漏“上回没看完的接着看”的引用片段；修复通用引用片段后，70 条成为回归集，不能继续称为未见准确率。
36 条拒绝在首次及正式 Router 回归均无执行候选；新自然正向用例也验证实际进入 CommandBus 边界。

最终另冻 24 条，冻结后未按其答案补词或调整解析：

- 基础语义 action/target/rating 严格 **20/24（83.3%）**；action 单项 21/24。
- 12 条否定、转述、询问、标题、冲突句 **0 个执行候选**。两批合计 48 条不同拒绝表达；这是有限语料结果，不是普遍安全保证。
- 3 条能力覆盖遗漏：“这曲实在乏味”“帮我挑部养眼的”“把这一首留在喜欢的里”，均安全拒识，未为了覆盖率猜测执行。
- 1 条对象提示偏差：“另换个排行榜”提取 current 而非 music；仍需实时情境，不能据此声称业务操作已正确。
- 其余执行链错误由实际 SQLite/控制器、状态竞争及 Qt/MPV 测试单独检查，不能用文本正确率替代业务验证。
- 单机温热 Router 240 次：p50 约 0.260 ms，p95 约 0.496 ms；不含 ASR、数据库、音源联网、MPV 和 TTS，不是整句语音响应时间。
- 语料由开发者独立编写，不冒充第三方盲测。历史 160/80 模型实验、答案及划分没有修改。

## 最少实机验收

1. 音乐起播：说“这首歌不好听”“这首一般般”，检查只切一首；说“不是换歌，是换榜单”，检查更换榜单及后续连续播放。
2. 说“这首不错”确认不自动加歌单，再说“这首不错，给我留着”两次；打开歌单检查只有一个条目，重启后仍在。
3. 音乐和电影分别测试“暂停会儿/继续播放”；打开电影时音乐应在实际起播后暂停，停止电影不自动恢复音乐；说“这个不好看”，检查原进度及替代候选。
4. 说“别再跳过这首啦”“他说这首不好听”“你是不是停了”；不改变播放。误评价后说“我不是让你换歌”，不反向切歌，只撤销可归属的弱反馈。
