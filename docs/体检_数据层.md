## ② 实现方式（数据源 / 依赖 / 触发链 / 限制）

### 配置文件

- **settings.yaml**：启动时 yaml.safe_load 全量读；`save_settings_yaml`（settings_store）带锁更新指定节（tts 节由设置页写）。历史：曾有"无锁直接写"路径（已收敛到 settings_store 带锁）。`intent: null` / `asr.ptt_key: null` 为合法 null 字段（功能未启用）。
- **music_dirs.json**：load_music_dirs 首次从 settings.yaml `music.scan_dirs` 种子，之后独立维护；save_music_dirs 带锁写。
- **ui_prefs.json**：**刚修复重入死锁**（Lock→RLock）。此前 save_ui_prefs 每次调用永久死锁 → 文件从未成功创建（本批次已实测修复并首次落盘）。现由 .gitignore 排除（运行时配置不进仓库）。
- **combos.yaml**：UI 保存时 yaml.safe_dump 整文件重写 → **注释会丢**（文件头已显式标注"此文件由 UI 保存时会重写，注释会丢失"——已知风险，用户接受）。
- **music_sources.json**：在线音源注册表。字段：name/api_url/search_path/song_url_path/enabled/source_type/added_time。**无 token/密钥字段**（实测仅 2 个 js 音源，api_url 均为公开地址）。

### 数据库

- **music.db**：SQLite **WAL 模式**（`PRAGMA journal_mode=WAL` + `synchronous=NORMAL`），单连接（`check_same_thread=False`）+ 应用层 `threading.Lock` 串行化写。表：music（唯一 path 索引）+ FTS5 music_fts（触发器自动同步）+ music_highlight。索引：artist/album/title/genre 4 个。
- **player.db**：每次 upsert/get 都新建连接再关闭（连接开销大但量小：每局每玩家一次写入）；主键 puuid 天然索引。**无 WAL**（journal 默认 DELETE 模式）。

### 缓存

- **SnapshotCache**：TTL 7200s（覆盖整局，注释说明 5min 会导致对局中段全过期）；惰性过期清理；`clear()` 局间调用；**无 size limit**——但量级为单局 10 人，安全。
- **OnlineCache**：TTL 300s；源注销时 `delete(source)` 清理；**无 size limit**——搜索词数量级小，安全。
- **intelligence_service._cache**：游戏结束 clear()；无 TTL——量级 10 人/局，安全。
- **overlay_assets**：dict 缓存，**不清理**——总量有界（~173 英雄头像 + 技能图标），安全。
- **EventLog**：`data/events/` 按日期一个 JSONL 文件，**无保留策略、无清理、无大小上限**——订阅全部事件（含 game.time_update 高频帧事件）。

### 静态数据

- `data/lol_data/` 8 个 json（abilities 208KB 最大），启动/懒加载进内存 dict，O(1) 查询（champion_catalog 等模块级单例）。

## ③ 对标（成熟软件）

| 项 | 本项目现状 | 成熟软件做法 |
|---|---|---|
| SQLite 维护 | WAL 从不 checkpoint、无 VACUUM | 定期 `PRAGMA wal_checkpoint` + 增量 VACUUM；异常退出自动恢复 |
| 事件日志 | 无限累积 JSONL | 日志按大小轮转 + 保留 N 天，自动清理 |
| 配置管理 | 多文件散落 + 部分注释丢失 | 单配置 + 版本化迁移 + 保留注释（YAML 定点改写而非整文件重写） |
| 缓存 | 全部 TTL 有界或量级有界 | LRU + 容量上限兜底 |

## ④ 增补候选

| 候选 | 标注 | 说明 |
|---|---|---|
| **music.db WAL checkpoint**（定时/关闭前 `wal_checkpoint(TRUNCATE)`） | 🟢 修复类 | **实测 WAL 4.2MB vs 主库 229KB（18 倍）**——写多读少的增量扫描场景 WAL 持续膨胀；加 1 行 checkpoint（或 close 时执行）即收 |
| **EventLog 轮转/保留策略**（超 N MB 切文件、保留 N 天） | 🟢 修复类 | **实测 data/events 21 文件 56.2MB**——game.time_update 1Hz 帧事件全量入库；加大小上限 + 旧文件清理 |
| **settings.yaml 定点改写保留注释**（combos.yaml 同理） | 🟡 能做但工作量大 | 需 yaml 注释感知库（ruamel.yaml）或改"行级 patch"；combos.yaml 文件头已标注注释会丢（已知） |
| **player.db 连接复用**（模块级连接 + 锁，替代每次 open/close） | 🟡 能做但工作量大 | 现每次 upsert/get 新建连接；量小但属明显优化点 |
| **测试残留清理**（data/test_music.db / tts_test.mp3 / _real_playerlist_sample.json / _shot.png） | 🟢 修复类 | 4 个本地调试/测试残留文件，不属运行时数据，可清理（_real_playerlist_sample 若仍要留作样例可移 docs/） |
| **config 目录整理**（ui_prefs 已 ignore；music_sources 无敏感字段已确认） | ⚪ 花架子 | 现状已可接受 |
| **数据文件版本化/迁移框架** | ⚪ 花架子 | 单人项目无迁移需求 |
