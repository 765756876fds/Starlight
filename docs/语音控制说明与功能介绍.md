# Starlight 语音控制说明与功能介绍

本文按当前代码整理，适用于源码运行和包含语音组件的 Windows 版本。语音识别使用本地 ASR/VAD 与确定性的规则匹配，不使用大模型猜测命令；没有匹配到规则时不会执行动作。

## 1. Starlight 语音功能简介

语音可以控制音乐、电影和部分英雄联盟辅助功能，也可以创建提醒、查询对局信息和记录技能冷却。识别流程是：麦克风或系统声音采集 → VAD 判断说话片段 → ASR 转文字 → 规则识别 → CommandBus 执行 → 状态反馈/TTS 播报。

语音输入和 TTS 必须在应用中正常初始化。LoL 命令还需要英雄联盟客户端连接；音乐、电影命令需要对应播放器或数据源可用。

## 2. 快速上手

1. 启动 Starlight，确认语音输入、ASR 和 TTS 初始化没有报错。
2. 选择正确的采集来源：麦克风用于环境声音，系统声音用于电脑内部音频（具体选项以界面为准）。
3. 用短而明确的一句话说命令，例如“播放周杰伦的晴天”或“暂停电影”。
4. 等待识别和执行反馈。搜索音乐、搜索电影、重新扫描音乐库等长任务会异步执行。

当前规则没有统一唤醒词要求。电影命令应明确说“电影/影片/片子”；裸“播放歌曲名”按音乐搜索处理。

## 3. 通用规则

- 一次只说一个动作，避免把闲聊和命令混在一起。
- 音乐和电影的暂停/继续最好带领域词：`暂停音乐`、`继续电影`。
- 游戏开关必须说清楚“打开/开启”或“关闭/关掉/停止”。
- 规则会忽略常见标点和句尾语气词，但不会理解任意同义句。
- 空识别结果保持安静；无法识别的非空指令通常提示“没有听懂这条指令，请说得更具体一些”，并有节流，避免噪声连续播报。

## 4. 全局语音控制

### 播放控制仲裁

裸说“暂停”时，会暂停实际在播的媒体，并保存已确认暂停的会话；裸说“继续”只恢复这次快照中的有效会话。明确说“暂停音乐”“继续音乐”只控制音乐，“暂停电影”“继续电影”只控制电影。无法确认状态时不会假装执行。

停止 TTS 播报可以说：

- “停止说话”
- “闭嘴”
- “别说了”
- “安静一下”

这些是语音播报打断命令，不是停止音乐命令。播报停止和队列当前项取消由运行时直接处理。

## 5. 音乐语音控制

### 播放与切歌

- “播放周杰伦晴天” / “来一首周杰伦晴天”：搜索并播放在线歌曲。
- “播放音乐”：播放当前本地歌曲或队列内容；没有歌曲时会提示先选择歌曲或说出歌名。
- “暂停音乐” / “继续音乐” / “停止音乐”：暂停、继续或停止当前音乐。
- “下一首” / “换一首” / “切歌”：切到下一首。
- “上一首” / “上一曲”：回到上一首。
- “播放当前榜单第三首”：播放当前榜单指定序号。

在线搜索和播放依赖已加载的音乐音源、Node 插件或其他在线来源；来源不可用时不能保证播放成功。

### 音量、跳转和播放模式

- “声音大一点” / “音量小一点”：调整音量。
- “音量加 10” / “音量减 10”：按步长调整。
- “音量 60”：设置 0–100 的音量。
- “快进 10 秒” / “后退 5 秒”：相对跳转，支持 1–60 秒。
- “随机播放” / “列表循环” / “单曲循环” / “顺序播放”：设置播放模式。
- “播放暂停” / “切换”：切换音乐播放/暂停。

### 高潮、队列和歌单

- “打开高潮模式” / “关闭高潮模式”：切换高潮模式。
- “播放高潮” / “跳到高潮”：跳到当前歌曲高潮位置（需要已有可用分析结果）。
- “播放我的歌单”：播放指定歌单。
- “新建歌单叫运动”：创建歌单。
- “把这首歌加到收藏歌单”：把当前歌曲加入歌单。
- “把歌曲名放到下一首”：加入下一首队列。
- “清空队列”：清空播放队列。
- “重新扫描” / “更新音乐库”：重新扫描本地音乐。
- “清理失效歌曲”：清理失效本地歌曲记录。

### 睡眠定时和识曲

- “睡眠定时三十分钟” / “睡眠定时六十分钟” / “睡眠定时九十分钟”：设置定时。
- “取消睡眠定时”：取消定时。
- “识曲” / “听歌识曲” / “这是什么歌”：打开识曲流程。

倍速命令已经有规则入口，例如“倍速播放 1.5 倍”“恢复正常速度”；缺少数字时会提示补充，实际支持的倍速档位由播放器控制器决定。代码和测试已覆盖，具体安装版仍建议实机确认。

## 6. 电影语音控制

### 搜索和播放

- “播放电影流浪地球”：通过电影搜索链路查找并播放。
- “看电影流浪地球第二集”：搜索并尝试播放指定集数。
- “播放下一部”：切换到下一部/下一集（取决于当前媒体链路）。

在线片源必须可用，搜索结果和播放地址由现有电影源决定。用户也可以在界面选择本地视频；本地文件选择、字幕、历史和窗口操作以界面入口为主，不应把它们误认为全部都有语音命令。

### 播放控制

- “暂停电影” / “电影暂停”
- “继续电影” / “恢复电影”
- “停止电影” / “关闭电影”
- “电影声音大一点” / “电影声音小一点”
- “电影音量 50”
- “电影快进 10 秒” / “电影后退 5 秒”
- “下一集” / “上一集”

电影停止在执行结果确认后才播报“电影已停止”；失败时会播报“电影操作未成功”。暂停、音量和跳转的反馈依赖控制器实际返回值。

## 7. 英雄联盟语音控制

### 使用前提

LoL 查询和自动化依赖客户端连接、当前游戏阶段和对应服务。自动排队遵循当前产品规则：用户先手动进入合法的人机大厅，Starlight 才继续自动匹配；不会无条件自动创建大厅。

### 对局查询

- “我现在几杀几死”
- “我现在战绩”
- “对面都有谁”
- “谁死得最多”
- “我几级”
- “亚索几级”
- “亚索战绩”

这些命令查询当前对局数据；客户端未连接、数据不可用或字段不足时可能无法确认。

### 技能与召唤师技能计时

- “对面石头人用了闪现”
- “石头人刚刚用了闪现”
- “石头人 R 了”
- “对面莎弥拉 W 用了”
- “闪现还有多久”
- “对面石头人的闪现还有多久”
- “取消石头人计时”
- “取消所有技能计时”

记录类命令要求明确动作词，例如“用了/交了/放了”；普通转述不会自动创建计时。取消后会根据实际取消结果反馈。

### 自动化开关和状态查询

| 功能 | 打开示例 | 关闭示例 | 查询示例 |
| --- | --- | --- | --- |
| 自动排队 | “游戏，打开自动排队” | “游戏，关闭自动排队” | “游戏，查询自动排队状态” |
| 自动同意 | “游戏，打开自动同意” | “自动接受，关闭” | “游戏，自动同意开着吗” |
| 自动禁用/选人 | “游戏，打开自动选人” | “自动禁用，关闭” | “游戏，查询自动选人状态” |
| 自动连招 | “自动连招，打开” | “连招总开关关闭” | “游戏，自动连招开了吗” |

打开成功、客户端未连接、配置缺失和执行失败会区分反馈。自动连招还要区分总开关与键盘监听器：可能出现“自动连招已开启，但键盘监听器不可用”，这不等于连招已经可正常执行。

## 8. 语音播报与执行结果

- 成功反馈由命令执行结果决定，不是只看 ASR 是否识别到“打开”或“播放”。
- 搜索播放和重新扫描是异步任务，反馈可能晚于识别日志。
- TTS 播报可用“停止说话”“闭嘴”“安静一下”等命令打断。
- 空输入保持静默；未知非空指令采用低频提示。
- 部分旧的音乐切歌、音量和队列命令主要依赖控制器/UI 状态，若执行器没有返回可确认结果，可能没有额外成功播报。

## 9. 常见问题

### 没有识别到语音

确认麦克风或系统声音来源选择正确，ASR/VAD 已初始化，且模型和后端可用。先说短句并避免环境噪声。

### 识别成 `system.unknown`

说明文本没有命中当前规则。改用表格中的短句，补上“音乐/电影/游戏”等领域词，并使用明确动作词。

### 识别成功但没有动作

检查对应模块是否初始化、播放器是否运行、LoL 客户端是否连接、在线音源是否可用。搜索类命令还要等待异步任务完成。

### 音乐能播放但在线歌曲失败

检查 Node 音源插件、网络和来源本身；在线歌曲需要能获得真实播放地址。没有地址时不能通过语音强制播放。

### LoL 自动化没有执行

先查询状态，再检查客户端连接和游戏阶段。自动排队需要先手动进入合法人机大厅；自动连招还需要键盘监听器可用。

### 没有 TTS 播报

查看 TTS 初始化和日志。部分命令本来只记录状态或由异步任务完成，不一定每一步都播报；不要仅凭没有声音判断命令未执行。

## 10. 当前已知限制

- 规则匹配不是自然语言大模型，未列出的表达可能无法识别。
- 真实麦克风、系统回环、ASR 后端、TTS、在线音源和 LoL LCU 行为需要在目标 Windows 环境单独验收。
- 在线音乐和在线电影依赖网络、插件或第三方服务的当前可用性。
- 本地电影选择、字幕匹配、播放历史和窗口交互主要通过电影界面完成。
- 电影播放位置记忆、收藏、稍后观看等未列入当前语音能力。
- 不能把代码存在或单元测试通过等同于真实 LoL 对局或在线服务已验收。

## 代码依据与版本说明

### 2026-10-30 对抗性回归补记（代码测试通过，待设备验收）

- 请直接说要做的操作。“如何取消所有技能计时”“石头人闪现用了是什么意思”等询问和转述不会创建或取消计时；带引号引用命令或询问“打开自动排队？”会要求说清楚操作。
- 说“电影音量”后，若不想继续设置，可以说“取消”“算了”“不用了”或“取消设置”。这只取消本次参数追问，不取消其他提醒。12 秒到期后也不再把裸数字关联到旧设置。
- “三四”“十十”“一百二”等含糊数字不会被猜成另一个数值；请说“五十”“一百二十”等明确数值。负数、越界和混用单位不作为默认参数执行。
- 音量加减会使用实际说出的步长。倍速不支持的档位、播放器执行失败、超时和无法确认结果会分别反馈，不再把所有失败都说成“不支持倍速”。
- 同一段识别文字包含不同参数、不同模块或否定句时，不会按文字相似度删掉其中一段后执行。请分次说“音量五十”“暂停电影”，不要合并成一条长句。
- 新指令到来后，尚未开始的旧搜索及尚未播报的旧结果会检查是否过期；不清除其他游戏提醒。这不能撤销已经发出的网络/播放器操作，也不代表会停止已经开始合成或播出的 TTS。
- 歌单添加失败不再一律当作“已经添加”。旧控制器没有返回完成证据时，可能提示“无法确认”或保持无额外成功播报，请结合界面状态判断。

完整使用场景、业务入口、反馈条件和未覆盖能力见 [语音能力矩阵](语音能力矩阵.md)；自动化测试和保证范围见 [语音对抗性回归验收](语音对抗性回归验收.md)。

### 2026-10-30 语义改进（代码测试通过，待设备验收）

- “把音乐声音调小一点”“音乐小声点”“音量降低一点”均调整音乐音量；电影同类说法必须明确带“电影”。“静音”将音乐音量设为 0，“电影静音”只调整电影。
- “倍速 1.5 倍”保留小数点，也支持全角数字。
- 说“倍速”“电影音量”“睡眠定时”缺少数字时会提示补充。12 秒内可以只回答“一点五倍”“五十”“三十分钟”。只关联紧接着的一次回复；其他指令、无法关联的回复、停止语音或超时会清除追问。
- 超范围音量和电影跳转不会送往播放器，不会因为参数缺失而使用默认音量 50。
- “游戏，打开自动同意”“查询自动接受状态”使用已有自动接受能力；查询不会变更开关。
- “查询当前技能计时”报告现有计时数量；“队友石头人交闪”保留目标、闪现和我方标记。
- 否定、明确转述和两条完整操作不会触发其中一个动作。多条操作请分开说。
- 音乐异步搜索会交回结果或异常；新指令会使旧搜索反馈失效。“正在加载”不代表已经实际起播。
- 两秒内重复送达的完全相同音频段只处理一次；不同录音仍可连续执行同一命令，不保证消除所有声学回声。

参数提示、字段及示例统一维护于 `app/voice/registry.py::PARAMETERS`，示例由测试验证；完整规则仍在 `intent.py`，不代表所有功能均已迁移到注册表。
