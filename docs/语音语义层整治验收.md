## 调用链

1. `VoiceRuntime._mic_loop`：PyAudio 采集与现有音量阈值 VAD 分段；未更换模型或后端优先级。
2. `_enqueue_speech → _asr_loop → _process_speech`：有界队列、ASR 转写；补上转写后及分发前代次检查，事件保留原始文本。
3. `text.normalize_text → RuleBasedIntent.match`：保留小数点、英文单词中撇号、否定；有限礼貌前缀和中文空格归一化。
4. `IntentRouter.parse`：明确指令优先，再尝试 12 秒内的一次数值补充；新指令、无关回复和停止运行清上下文。不继承游戏写操作。
5. `registry.parameter_issue → Runtime → CommandBus`：参数缺失、越界先拦截，原业务返回契约不强制统一。
6. `CommandBus.execute_async(on_done=...)`：一次执行、一次完成回调；反馈失败记录日志，不重试业务。
7. SpeechQueue：音乐搜索由 Runtime 反馈；电影正常提示仍由控制器负责，避免双重播报。过期反馈被丢弃。

## 限制

- 旧音乐搜索返回 None 同时可能代表空结果、音源失败或未知状态；本轮反馈未知，不捏造精确原因。
- 请求检查不能撤回已发出的 HTTP/MPV 命令；电影进入 play() 后的细粒度取消暂缓。
- 已排队或正在播报的旧 TTS 不做全队列清空。
- 只做有时限的数字参数追问，不做聊天记忆、多动作自动计划。
- 两秒相同音频防重不保证识别所有声学回声或不同音频的重复转写。
- settings/diagnostics 尚无统一业务命令入口，不模拟 UI 私有方法；VOICE_ENABLE/TTS_ENABLE 常量也不代表已接线能力。
- 未动 ASR/VAD/TTS 引擎、MPV 生命周期、LoL 排队规则、音乐高潮算法及安装资源。
- 真实麦克风、回环、TTS、Windows MPV 和真实 LCU 需单独验收。本轮不打包、不提交、不推送。
