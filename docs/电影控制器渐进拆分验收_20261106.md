# 电影控制器渐进拆分：CMS 纯解析边界

## 范围与收益

基线提交为 `03acf8838eaed4e5b11640db4c2cdcd90a74af33`。本轮只抽取一个边界：CMS 响应与分集地址解析。控制器原有 78 个方法保留，播放器、网络调用、线程、历史、字幕和 UI 接线不改。

四个函数移至 `app/movie/cms_parser.py`：`parse_cms_response`、`split_play_url`、`first_play_url`、`episode_eps`。其语法树与原实现逐一相同；`movie_controller.py` 继续导出同名函数，包级旧入口也保留。新模块只依赖标准库 json，无网络、文件读写、Qt、MPV 或数据库操作，可单独验证格式兼容，避免后续解析维护牵涉控制器资源。

注意：`app.movie.__init__` 仍沿用原有的控制器 eager 导入；本轮不宣称普通包导入已完全消除控制器初始化，也不顺手修改包加载方式。

## 原控制器职责地图（抽取后的函数名与位置）

| 职责 | 入口与依赖 | 保留的边界 |
| --- | --- | --- |
| 搜索与来源 | search、_search_one；MovieSourceManager、requests | 来源降级、超时、结果字段、来源标记不改；只将响应/地址解析委托给纯模块 |
| 元数据与选集 | episodes、is_multi_episode；content_classification | 分类与标准化已有独立模块，不再另建；保留段数和备注双判据 |
| 播放 | play、play_external_url、_advance_episode、pause/resume/seek | 独立 MPV、音乐互斥、明确 IPC 成功、集数及当前上下文保持 |
| 字幕 | _local_subtitle、subtitle_state、load_local_subtitle、search_subtitle、load_subtitle | 本地发现/路径去重、轨道控制、Assrt 与归档提取保留；Assrt JSON 继续使用相同解析函数 |
| 续播与历史 | _save_local_progress、stop、close、history_item、_record_history_if_started | watch_later 有界保存、失败不阻断关闭；MovieHistory 存储与本地库不改 |
| 状态与事件 | _write_state、_subscribe、_on_music_playing、_on_shutdown | StateStore 与 EventBus；控制器自身不是 Qt 控件，不新增 Qt 信号/槽 |
| 生命周期 | tick、restart_current、_restart_worker、close | 面板定时 tick、恢复锁/字幕锁、后台恢复线程及限次恢复保留，不改变关闭顺序 |
| 命令适配 | _register_commands、_cmd_search_play、_notify_voice | 旧命令参数、结果和过期守卫不改；海报双击搜索与语音直达播放是不同的既有入口 |

直接调用方：main.py 创建控制器，MoviePanel 发起搜索/播放并轮询，VideoPlayerWindow 使用播放/字幕接口并延迟导入 split_play_url。调用方向仍为 UI/启动入口 → 控制器 → 来源、历史、MPV；新纯模块仅依赖 json，不新增反向引用或循环依赖。未进行无关全项目循环依赖审计。

## 兼容性证据

- 保留 JSON 对象/数组、前导空白、非 JSON 和坏 JSON 的既有返回约定；不擅自扩大非字符串输入契约。
- 保留第一个 `$` 分隔、分集顺序、重复条目、空名称及无效片段过滤。
- 新增测试执行真实 `_search_one` 与 episodes/is_multi_episode；只替换外部 HTTP 响应，不建立真实播放器或用户历史库。
- 旧控制器导出与新模块函数为同一对象；旧 UI 和包级导入继续可用。
- 导航六分类、日夜主题、海报单击详情/双击一次搜索、旧请求隔离、禁止自动播放、官方入口、本地打开、字幕和续播均由相关既有测试保护。

## 剩余耦合与停止点

搜索仍在控制器编排来源与字段转换；字幕包含网络、归档和轨道管理；恢复线程与播放上下文、tick 和关闭流程仍耦合。这里只记录边界，不把未经复现的风险认定为缺陷，不继续抽取第二个模块。未来仅在有实际修改需求时考虑独立的纯字段映射；线程/播放器/历史拆分需要专门生命周期证据，不因文件较长而实施。

本轮不新增运行时依赖、后台进程、数据库或持久配置；没有额外网络请求。未另做 CPU/RAM 基准。原有 20 个 tracked 修改、39 项未跟踪文件保留；维护文件只追加本轮记录，暂存时只选择本轮增量。
