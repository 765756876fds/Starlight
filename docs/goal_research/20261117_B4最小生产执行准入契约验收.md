# B4：LISTEN_MUSIC 最小生产执行准入契约

执行日期：2026-11-17。基线：`1d5af81b969d783adda9af5582a18a4ce594696f`。这是默认不用的新业务接口，不是正式语音接线或用户实机验收。

## 结论与范围

正式 `MusicController` 现在可以拥有一个显式创建的准入对象，复核外部已选定的计划，并通过原有播放与推荐业务执行。它不选择榜单、不解释自然语言，不注册新命令，不修改 VoiceRuntime、CommandBus、偏好库结构或队列算法。

支持 `NO_OP / RESUME_MUSIC / TRY_COLLECTION / TRY_CHART`。收藏仅支持权威临时/正式数据库中的本地成员；在线收藏缺少足够的身份与执行契约，本轮不接入。榜单复用原推荐器；本轮真实 MPV 验证所用榜单源完全本地，不能外推为真实在线平台成功。

## 正式接口与归属

新增 `app/music/goal_admission.py`，由控制器惰性创建，外部不能以实验门闩代替控制器锁：

| 控制器接口 | 契约 |
| --- | --- |
| `goal_state()` | 工作线程采集控制器状态戳与 MPV 只读属性，前后复核一致性 |
| `goal_member(playlist_id, member_id)` | 在数据库所有者锁内取得权威本地成员身份与文件证据 |
| `admit_music_goal(GoalRequest)` | 有界准入、重复 ID 幂等、旧请求拒绝、共享既有业务 |
| `observe_music_goal(operation_id)` | 工作线程观察对应 MPV 条目、路径与连续进度，发布可归属回执 |
| `cancel_music_goal(operation_id)` | 失效指定操作；不声称撤销已经发送的 MPV 指令 |

`GoalRequest` 包含唯一操作 ID、固定 Goal、四种允许计划之一、预期 `StateToken`、可选 `MemberToken`、单调截止时间和 `threading.Event`。不接受任意业务函数或调用者提供的取消回调；内部生成的 guard 才能进入受锁路径。请求截止须为未来 5 秒以内，状态快照有效窗口为 1 秒。真实慢源仍由原音源池及桥接超时清理，不新建常驻线程。

`StateToken` 绑定控制器 UUID、用户操作 revision、播放请求代次、播放会话、当前内容身份、队列 revision、暂停/停止状态、来源管理器及其版本/关闭/注册状态、采集时间、实际媒体状态和 MPV entry ID。`MemberToken` 绑定歌单 ID、稳定成员 ID、权威关联行内容摘要和文件身份。接口不持久化标题、文件路径或 URL。

## 准入时点、锁序与剩余边界

准入线性化时点是持有控制器锁、完成必要权威成员复核后，将操作登记为唯一 `_active`。它表示业务所有者接收了操作，**不是 SQLite 与 MPV 形成原子事务**。

- 获取顺序：控制器锁 → 数据库所有者 RLock（仅收藏提交窗口）→ 极短回执锁；队列/来源读取使用各自有界锁。回执锁内不等待控制器、数据库或 IPC。`current()` 释放回执锁后才检查来源和文件。
- 控制器、数据库、来源、队列的新增锁等待通常限制 20ms；MPV 专用加载门闩等待 20ms，已有 RPC 的加载回执预算不超过 200ms。恢复复用原 `playback_lock` 的 200ms 获取限制。
- 本地收藏从权威成员查询、文件复核到共享队列提交与有界 loadfile ACK 期间保留所有者锁；不跨联网解析或真实起播确认持锁。数据库忙超时临时缩短并准确恢复，不迁移、不 checkpoint。
- 拒绝未知 schema、关闭数据库和已有未提交事务；不替调用者提交或回滚原事务。在本次独占窗口中新产生、因异常未提交的事务才回滚；已提交历史不伪装成可撤销。
- 经受控数据库方法删除成员，与准入串行；手动操作在等待控制器锁前递增所有者 revision，因此正在等待锁的新操作也能阻止旧计划随后发出 loadfile。
- 本轮保护公开受控入口和既有队列通知/播放代次。原始外部 SQL、其他进程改文件、直接操作 MPV、私有属性写入、自定义慢事件订阅者，不是一个跨进程事务，也不能声称全部被统一接管。
- 本地文件的存在、可读、身份未变不等于可解码；文件系统和 Windows 调度不是硬实时。首次试运行应限本地磁盘，不能把网络盘、失效设备或任意回调的时间上界理解为已证明。
- 源注册/关闭证据在准入和实际发送前复核，但没有把来源管理器与数据库组成分布式事务。后续正常用户操作与来源更新将使旧回执/计划过期；已经发送的命令只能如实标记可能有副作用。

## 状态与真实起播

| 回执 | 含义与后续 |
| --- | --- |
| `REJECTED_STALE` | 身份、版本、成员、资源、权限或取消发生变化；不得继续旧计划 |
| `REJECTED_UNAVAILABLE` | GUI 调用、锁忙、播放器/源未就绪、已有业务/未决操作；未受理 |
| `FAILED_NO_EFFECT` | 正式业务前失败，确认尚无播放相关修改；读取失败不是空收藏 |
| `ACCEPTED` | 已受理，可能正在解析/加载；`mpv_accepted` 单独表示 ACK，不代表起播 |
| `UNKNOWN_EFFECTS` | 已修改队列/进入业务或 IPC 结果不明，不允许外层自动回退 |
| `STARTED` | 对应 MPV 路径、条目、非 idle、非暂停与两次推进的有限数值进度共同成立 |

`PlaybackProof` 保存 entry ID、前后位置、单调观察时间及内容摘要。新播放必须看到不同于旧快照的 entry；NO_OP/恢复必须仍为原 entry。读取前后再次检查请求 revision，避免拼接新旧媒体证据。STARTED 是该时刻的证明，不是未来永久播放保证，也不是扬声器已发声证明。

重复操作 ID 和相同请求返回既有回执，不重放；同 ID 不同载荷拒绝。回执最多保留 128 条，没有新增回执轮询线程。调用者需有界观察，放弃操作时明确取消；副作用不明不能靠重复创建计划解决。

仅 `FAILED_NO_EFFECT/resource_not_attemptable` 且未开始业务时，`safe_to_fallback` 才为真。权威读取异常/忙、未知 ACK、状态过期都不授权自动换方案。未决操作占用准入；同代次自动接续暂停推进，防止坏文件确认线程或 EOF 在外层未决时再启动另一首。正常起播确认后解除；手动操作仍可接管。旧默认流程没有准入所有者时继续使用原行为。

既有推荐器内部 45 秒总预算、20 秒单次读取、最多两个未结束源读取保持原实现；B4 guard 受更短请求截止约束，轮询约 100ms 检查。第一条 loadfile 结果不明即阻断既有推荐器内部重试，不叠加外层三轮预算。已运行的音源任务不能凭 Event 强行终止，仍由既有桥接超时收尾。

## 手动操作和跨媒体边界

原公开用户操作装饰器、在线播放/换源/列表入口、推荐入口及队列 revision 变更使旧计划失效；内部恢复和推荐调用只以该操作自己的 guard 免除自取消。旧请求的晚到 URL 不得覆盖新歌；loadfile 已 ACK 后发生取消，也不得继续发布旧当前曲目或建立旧推荐队列。

有副作用的计划要求电影 `playing` 明确为 False；True/未知时拒绝。NO_OP 只读证明现有音乐目标，不改变电影，不需要取得跨媒体控制权限。B4 的榜单播放不调用旧电影暂停回调；现有 V1 调用仍按原逻辑处理。该检查不是新的跨媒体仲裁器，正式并行试运行仍需上层提供可靠状态及清晰授权。

关闭后准入对象保持关闭；不擅自跟随模块重启重新启用。调用者若需要新一轮试运行应重新创建测试控制器或另行定义启用生命周期。
