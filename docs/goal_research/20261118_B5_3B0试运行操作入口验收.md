# B5.3-B0：首次用户试运行操作入口

执行日期：2026-11-18（Asia/Shanghai）。本轮只补装配、临时开关、状态/路由和资源范围，不新增 Goal、不启动用户程序或麦克风。

## 结论与用户操作

**已具备由用户亲自开启的限定试用入口**。首次范围为 NO_OP、RESUME_MUSIC，以及 B4 准入前一次性选择旧 V1 推荐。**本地收藏自动选择暂不开放**，在线榜单仍由原推荐器处理；本轮仅使用本地确定性音源替身验证，不代表真实网络或麦克风验收。

1. 用户先正常退出托盘内的旧星芒；否则现有单实例机制会唤醒旧进程，不能证明运行的是新源码。本轮没有替用户退出或启动它。
2. PowerShell 源码启动（不需要修改私人配置）：

   ```powershell
   Set-Location -LiteralPath 'C:\娱乐助手\Starlight'
   & 'C:\娱乐助手\Starlight\.venv\Scripts\python.exe' -B 'C:\娱乐助手\Starlight\main.py'
   ```

3. 打开 **设置 → 语音 → 实验功能：智能听歌决策**，勾选“本次运行启用（仅‘我想听歌了’）”。初始未勾选，退出重启后仍关闭；不写 settings.yaml、数据库、QSettings 或环境变量。
4. 用户自行开启原有麦克风入口，说“我想听歌了”。设置页显示最近路由、方案、回执和操作编号；日志位于现有源码日志目录的 `logs/app.log`，过滤 `[ListenMusicTrial]`。通用 `music.recommend` 不是 B5 生效证明。
5. 再次取消勾选：无未决操作时，**下一次**同类请求走 V1。已发送的指令不能撤销；执行/观察中继续收尾，副作用未知时仍保护该入口，不能通过开关重置或换编号重复播放。

最少实机检查：默认关闭请求一次 → 手动已有音乐播放后开启，请求应 B5/NO_OP 且不重载 → 暂停后同句应 B5/RESUME_MUSIC → 无会话且来源具备能力时应 V1_PRE_ADMISSION → “下一首”和指定歌曲仍走原流程 → 关闭后新请求应 V1。仅实际回执 `started` 且存在对应进度证据才是 B4 起播确认；`accepted`/`unknown_effects` 不是播放成功。

## 装配与生命周期

- `main.py` 在原 VoiceRuntime/providers 初始化后调用 `_assemble_listen_music_trial()`，创建一个默认关闭的 ListenMusicTrial，使用 `GoalAdapter.for_user_trial(self.music)`，并通过已有 `bind_listen_music_trial()` 绑定同一 MusicController/CommandBus。重复装配幂等；装配失败隔离，保留 V1。
- `_switch_to_tabs()` → MainTabs → SettingsPanel 传递同一个 trial；语音页嵌入 ListenMusicTrialControls。不创建第二个 Bus、播放器、线程池或服务。
- 开关只改运行期许可和取消标记。状态使用 Qt 排队信号，控件只读元数据；后台不访问 Qt 控件，GUI 不做 SQL、IPC、文件检查或播放等待。排队状态到达时读取最新元数据，避免旧消息翻转开关。
- `Application.stop()` 在正常关闭链前取消入口并关闭 Adapter，初始化中止也会取消；原 VoiceRuntime/MusicController 的停止与自愈实现不改。
- 新装配核查发现：新建电影控制器可能尚未发布 playing=False。只在**开启后精确目标请求的原命令工作线程**，有界获取电影所有者锁；仅当从未加载、无当前内容、非外部播放、非停止中且实际进程不存在，才由原 `_write_state()` 发布初始空闲。曾加载过、进程状态未知、活跃或锁忙一律不补写；默认关闭不运行该准备过程，也不操作电影。

## 路由与回执

|标识|含义|执行边界|
|---|---|---|
|V1|默认关闭且无未决保护，保留原推荐返回对象与参数|不调用新 prepare/admit|
|B5|精确目标获许可，判断状态并执行/拒绝|NO_OP、RESUME 经 B4；其他不可靠状态不猜测|
|V1_PRE_ADMISSION|可靠且允许的冷启动已选择旧推荐器|先验证原快照及资源版本，再经原控制器短准入作用域转交；没有 B4 执行后回退|

日志只新增通知操作编号、上述路由、有限计划名与回执类别，不写文本、曲名、文件路径、URL 或令牌。旧请求不能改写新操作的诊断。V1 结果原样返回；诊断不代替通知中心原有结果契约。B5 仍通过 B4 的正式准入与观察，不直接控制 MPV。界面区分默认、开启、执行/观察中、未决保护；开关确认不等于播放确认。

## 正式资源范围

- 原隔离构造入口及 isolation_root 检查保留，原隔离收藏能力仍可验证。
- 新 TrialResources 只认可控制器当前的 music.db / music_preferences.db 两个精确管理路径，同一非磁盘根父目录；拒绝目录越界、UNC、各级符号链接/Windows 重解析点、非普通文件和硬链接。Windows 使用规范化绝对路径；构造只做词法处理，文件检查在命令工作线程执行。
- 首次试用 **不查询歌单成员、不读取偏好 SQL、不检查私人音乐文件、不生成 TRY_COLLECTION**，并在 execute 再拒绝伪造的本地计划；不以整个磁盘/测试目录伪装授权。收藏“未授权”不等于用户没有收藏。
- 冷启动只读取原有源的已注册能力及缓存元数据，并保留控制器数据库版本检查，不调用 `RecommendationService.choices()` 获取快照。真正选择 V1 后仍由原业务读取其数据和解析候选。
- 路径验证不是与文件系统组成原子事务；尚未建立私人音乐目录的明确授权和替换防护，故本轮不开放自动收藏执行。未知音乐/电影状态仍拒绝或待确认，不为了冷启动绕过权限。
