# 全项目功能体检报告 —— 音乐模块

> 只读调查（2026-10-12），不改代码。数据来源：app/music/ 全模块代码、config/settings.yaml、config/music_dirs.json、config/music_sources.json（结构，不打印内容）、main.py 接线。

## ① 现有功能（能做什么）

### 本地播放
- **扫描入库**：增量扫描（按文件 mtime 判断是否更新）+ 全量重扫；6 种格式（mp3/flac/wav/m4a/ogg/ape）；mutagen 读 ID3/FLAC/MP4/OGG 标签；坏文件自动跳过防卡死；清理失效歌曲（MUSIC_CLEANUP）
- **模糊搜索**：SQLite FTS5 + BM25 + difflib 相似度；歌名清洗（去括号/后缀 DJ版/remix/伴奏 等）
- **播放队列**：顺序/随机/单曲循环/列表循环 4 种模式；播放历史
- **mpv 播放**：命名管道 IPC（\\.\pipe\lol_music_mpv）；音量/seek/进度；自动切歌（0.8s 轮询 idle-active，因 IPC 事件回调不可达）
- **高潮跳转**：本地纯 CPU 高光检测（librosa+scipy，v4_early_rise，15-75s 窗口），语音"播放高潮"跳副歌

### 在线播放
- **音源管理**：多音源并行搜索（ThreadPoolExecutor 4 线程）、5s 缓存 TTL、版本锁防旧结果回写污染、定向路由取播放 URL
- **内置音源**：JS bridge（酷我，已验证可匿名播放、优先选）、通用 HTTP JSON 源（自定义 api_url/search_path/song_url_path）、demo/archive（默认禁用）
- **语音点歌**：本地搜索 → 找不到自动在线 fallback → 播放在线 URL（带 Referer 头处理酷我跨源）

### 外部播放器
- **落雪音乐（LX）优先**：HTTP API（127.0.0.1:23330）控制本地运行的落雪播放器；已连接时语音控制优先走落雪

### 语音控制（意图 → CommandBus 16 个 music.* 命令）
下一首/上一首/暂停/继续/播放切换/音量±（"音量加5"）/设置音量/单曲循环等播放模式/搜索播放（"播放XX歌"）/跳高潮/高潮模式/重扫/清理失效歌曲

### UI
- 音乐面板（播放控制、队列、扫描按钮、当前歌曲信息）；设置页音乐组（目录管理：多目录+启用勾选+格式过滤+排除子目录；音源管理对话框；默认音量滑块；扫描全部按钮）

## ② 实现方式

### 数据从哪来
| 数据 | 来源 |
|---|---|
| 本地曲库 | 文件系统扫描（settings.yaml music.scan_dirs / music_dirs.json），SQLite（./data/music.db，WAL，FTS5 索引 music_fts） |
| 在线搜索/播放 | JS bridge → 酷我等（data/music_sources/musicfree、lx 插件脚本 + node）；自定义 HTTP 源（config/music_sources.json 的 sources 节，含 token 等敏感字段） |
| 高潮位置 | 本地解码分析（librosa 加载音频，CPU 计算），入库 music_highlight |

### 依赖什么
- **外部程序**：mpv.exe（D:\新建文件夹 (2)\mpv.exe）、落雪音乐（可选，未装则降级本地 mpv）
- **库**：mutagen（标签）、librosa/scipy/numpy（高光检测，纯 CPU 后台）、requests
- **node**：JS bridge 需 node_modules（仓库内已带 package-lock + node_modules）
- **数据文件**：champions.json 无关；music.db 运行时生成

### 怎么跑通（触发链）
```
语音 → ASR → intent（正则） → CommandBus(music.search_play) → controller.play_search_result
     → search.py（FTS5 本地 top10）→ 命中：play_song → queue → mpv IPC
     → 未命中：online_manager.search_all（多源并行+缓存）→ 酷我优先 → get_play_url 定向路由
     → mpv 带 Referer 播放
自动切歌：mpv idle-active 轮询（0.8s）→ 播完 → queue.next → play_song
高光：highlight_detector.detect_highlight → 入库 → jump_to_highlight 跳转
```

### 有什么限制 / 已知缺陷
- **mpv IPC 事件回调不可达**（历史注释承认）：自动切歌必须靠 0.8s 轮询，实时性 ~1s 延迟；on_property_change 回调形同虚设（死代码路径）
- **在线源稳定性依赖外部**：酷我匿名可播（已验证）；demo/archive 慢且默认禁用；自定义 HTTP 源失败有分类错误（SourceError）不影响其他源，但无重试
- **music_sources.json 含敏感信息**（token 等，之前调查确认）——已被 git 跟踪（config/ 下），需注意误推风险（已在仓库历史中）
- **无歌词显示链路**（在线 manager 头注释写了"歌词"能力，实际消费未核实——待核实）
- **无播放进度记忆**：重启后不续播
- **无断网降级 UI 提示**：在线失败仅日志/空结果
- **highlight 检测重**：librosa 解码整首歌（CPU），扫描期可能卡；有 _highlight_running 防重入
- **单曲搜索取 top1**：语音"播放XX歌"直接播 index 0，无候选确认交互

## ③ 对标（成熟软件）

| 能力 | 网易云/QQ音乐 | 本项目 | 差距 |
|---|---|---|---|
| 曲库 | 千万级版权曲库（需登录/会员） | 本地文件 + 在线源（酷我等） | 曲库是数量级差距，但本项目定位是"语音控制本地/在线播" |
| 歌单管理 | 创建/收藏/分享歌单 | ❌ 无 | 缺歌单/收藏/最近播放 |
| 歌词 | 滚动歌词 + 逐字卡拉OK | ⚠️ 无（在线源有 lyric 数据但未接 UI） | 待核实 |
| 搜索体验 | 搜索页 + 候选列表 + 相似推荐 | 语音直接播 top1，无结果浏览 UI | 缺"搜索结果可浏览/多选" |
| 推荐 | 每日推荐/私人 FM（算法） | ❌ 无 | 依赖大数据，非本定位 |
| 音质 | 无损/高品/标准可选 | mpv 直放源文件 | 本地无损天然全支持；在线源音质不可选 |
| 播放控制 | 完整播放器 UI + 桌面歌词 | 面板 + 语音 | 缺桌面歌词/锁屏控制（非本定位） |
| 独家能力 | — | 语音控制 + LoL 对局集成 + 本地高潮检测 | 成熟软件没有 |

**结论**：作为"游戏对局中的语音音乐助手"，核心链路（语音点歌→本地/在线播放→自动切歌→高潮）已闭环，且高潮检测是独有亮点。缺的是"内容管理类"（歌单/收藏/歌词/搜索 UI），这些是锦上添花。
