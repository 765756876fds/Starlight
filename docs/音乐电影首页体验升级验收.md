## 3. 电影实际加载与去重

- 发现页调用 `MovieDiscovery.read('all', limit=6)`，服务只向UI交付每类最多6条；点击分类再取得该分类完整列表。
- **当前 B站接口不支持分页**：首次首页仍发出电影、电视剧、动漫3次完整分类请求，底层保留完整响应缓存。这次减少的是UI显示和绘制量，不是宣称把服务器的100条响应变成6条。
- 30分钟服务缓存保留；点击电视剧分类可直接复用其完整缓存，未过期时不额外请求。刷新分类只刷新该分类。返回发现页复用已渲染预览。
- 读取仍在后台，使用已有 LatestTask 的代次保护；A未完时切电影、再切电视剧，只保留最后待办，旧结果不切回旧页面。不能撤回已发出的HTTP。
- 一类或一个平台失败时保留其他结果，有旧数据时标过期并保留原时间；网络失败、正常空榜单、尚未接入分别反馈，不都显示成功。
- 去重沿用片名、年份、类型、地区及季数的保守规则，新增综艺同季规则。不同年份、不同季数和不确定身份不合并；合并后保留各平台排名。

## 4. 音乐首页最终布局

原在线子页成为发现工作台，现有5个主TAB及音乐本地/历史/歌单/榜单入口保留。

- 顶部：搜索、搜索音源范围、版本标记筛选、搜索按钮、发现首页。
- 内部分类：**推荐 / 排行榜 / 歌单 / 新歌 / 歌手与专辑 / 最近播放**。
- 首页六区：今日推荐、热门排行榜、精选歌单、新歌推荐、最近播放、我的歌单，每区最多6条。
- 搜索结果与发现首页分开显示；未搜索时不再留一个空结果框。返回发现页后，晚到的搜索结果不会抢回页面。
- 队列、歌词、识曲和列表视图按钮收进现有音乐子页标签栏，保留原控件/信号，腾出一行内容空间。
- 卡片保留来源与版本。现场/翻唱筛选只使用标题中明确的 Live、现场、Cover、翻唱标记，不据此推断原唱，不合并相同ID但不同来源的曲目。

### 插件能力与按需读取

- 推荐来自当前音源的公开分类歌单，未新增私人推荐账号或个性化算法。首页今日推荐展示首6个，精选歌单展示后6个，避免重复填充。
- 首页读取榜单**目录**，不预先加载每个榜单全部歌曲；双击榜单后才读详情。新歌区只列音源真实提供、名称明确标有新歌/新曲等的榜单，不拿普通热歌榜冒充。
- 分类歌单首批使用插件现有分页；查看全部和加载更多继续用现有API。曲目详情进入原结果列表，继续复用播放、右键队列和歌单入口，不修改播放器。
- 歌手/专辑按插件实际导出的 `search(...,'artist'/'album')`、`getArtistWorks`、`getAlbumInfo` 读取；名称、页码、原始条目和来源保留。没有能力时显示空状态，普通歌曲搜索照常。
- 最近播放、我的歌单复用既有控制器/数据库，进入原处理入口；没有另建收藏或播放记录系统。
- 发现目录和浏览结果使用120秒有限内存缓存（浏览最多32项）；返回首页复用成功数据。主动刷新绕过缓存，失败不记成正常空结果，支持立即重试。
- 分类/音源切换会隔离旧浏览结果；慢歌手请求不能覆盖后来选择的排行榜。各后台完成统一回GUI主线程，不会启动第二套播放队列。
