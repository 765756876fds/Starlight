## 本轮修复及前后证据

1. **影视缓存旧写覆盖新写**：受控线程 A 先开始、B 后开始先完成；原先缓存最后变回 A。增加每来源/分类的读取代次，仅最新启动的读可更新缓存，且写入副本，保留已经发出的操作结果，不宣称取消 HTTP。
2. **音乐榜单假空成功**：真实 Node 子进程中，插件详情返回 `null` 或 `{}` 原先产生成功空列表，目录返回 `null` 原先没有失败信息。现在校验已声明方法的真实返回结构；正常空数组保持成功，异常独立进入部分失败，重试能真正再次调用。
3. **刷新曲目页重复累加**：真实 Qt 事件循环中，刷新第一页变成 `[page1,page1]`，刷新第二页变成 `[page1,page2,page2]`。现在按当前集合的页号替换该页，首屏刷新重置后续页；保留实际不同页面中的重复 ID/歌曲版本，不按歌名去重。
4. **混合 Qt 回归迟初始化主题**：当前版与施工前副本同一 13 文件命令均在 `ThemeManager.__init__ -> app.setStyle('Fusion')` 产生 access violation，退出码 `3221225477`。两个旧音乐 UI fixture 没有像 main.py 一样先初始化主题。只修 fixture 初始化顺序、不改业务和断言；相同组合随后完整 262 passed。Qt 内部具体原生破坏位置未取得 dump 证明，不承诺消灭所有原生竞态。

首次四个复现用例为 4 failed，修后 4 passed；目录假空探针另为 1 failed，修后通过。首次原生异常、基线对照和中途失败日志全部保留，没有无限重跑。
