# LoL × 本地音乐 × 语音 Agent（lol-music-agent）项目全量技术报告

> 面向读者：Deepseek（AI 助手）与项目所有者（非程序员）。
> 目的：让读者完整理解"这个软件是什么、实现了哪些功能、每个功能是怎么想、怎么做的、程序是怎么跑起来的"。

---

## 一、项目一句话定位

一个跑在 Windows 上的**语音控制的英雄联盟（LoL）游戏辅助 + 本地音乐播放器**。
你对着麦克风说一句话（"播放周杰伦的晴天"、"对面石头人闪现了"、"随机播放"），它就能听懂并执行——播放音乐、语音播报游戏信息、记录技能冷却等。全程本地运行，不需要联网（在线音乐除外）。

## 二、技术栈与环境

| 项 | 内容 |
|---|---|
| 语言 | Python 3.11（Windows） |
| 界面 | PySide6（Qt 桌面框架，主窗口 + 状态栏 + 悬浮窗 Overlay） |
| 数据库 | SQLite（音乐库、高光位置、玩家比赛历史等，内置无需安装） |
| 语音识别 ASR | Qwen3 多模态模型，由 llama-server（本地 HTTP 服务，端口 8080）提供，启动时自动拉起 |
| 语音合成 TTS | edge-tts（微软 Edge 在线语音，本地生成音频） |
| 音乐播放 | mpv 播放器（独立进程，通过 JSON 管道 IPC 控制，Python 不直接碰音频） |
| 游戏数据 | 英雄联盟客户端 LCU API（本地 WebSocket/HTTP，读对局内实时数据）+ 腾讯 SGP 接口（比赛历史/段位）+ 腾讯 GSM 接口（对局内双方玩家身份补充） |
| 关键库 | requests、websocket-client、pydantic、PyYAML、mutagen（音乐标签）、librosa/soundfile（高光分析）、pyaudio（麦克风）、psutil、loguru |

## 三、系统架构总览

程序由 7 个模块组成，关系如下（箭头 = 数据流动方向）：

```
                    ┌─────────────────────────────────────┐
                    │            main.py（总装）            │
                    │  负责启动所有模块、接线、停止、退出    │
                    └───────────────┬─────────────────────┘
                                   │
        ┌──────────────┬───────────┼───────────────┬──────────────┐
        ▼              ▼           ▼               ▼              ▼
   ┌─────────┐   ┌─────────┐ ┌─────────┐   ┌──────────┐   ┌──────────┐
   │  voice  │   │  music  │ │   lol   │   │  speech  │   │  player  │
   │ 语音输入 │──▶│ 音乐播放 │ │ LoL 辅助 │──▶│ 语音输出 │   │ 玩家情报  │
   │ ASR+意图│   │ 本地+在线│ │ 对局数据 │   │ TTS+播报 │   │ 段位/战绩 │
   └────┬────┘   └────┬────┘ └────┬────┘   └────┬────┘   └────┬────┘
        │             │          │             │             │
        └─────────────┴──────────┴─────────────┴─────────────┘
                              │
                     ┌────────▼────────┐
                     │  core（地基）    │
                     │ 事件总线/命令总线 │
                     │ 状态库/调度器/日志 │
                     └─────────────────┘
```

**core（地基）**：全程序的中枢。
- **事件总线 EventBus**：模块间"喊话"用的广播频道（比如"对局开始了"这个事件，任何模块都能订阅）。
- **命令总线 CommandBus**：语音识别出来的意图 → 转换成标准命令 → 发给对应模块执行。
- **状态库 StateStore**：全局共享状态（是否运行中、麦克风开关等）。
- **调度器 Scheduler**：定时任务（如游戏内计时器的循环检查）。
- **日志**：控制台输出 + 事件记录（data/events，可复盘）。

## 四、程序是怎么启动的（执行方式）

`main.py` 是唯一入口。启动顺序（控制台会打印 `[0/5]` 到 `[5/5]` 步骤）：

1. **0. EventLog**：先启动事件记录器（最早的日志，一切操作可回放）。
2. **1. 音乐模块**：创建 MusicController → 注册在线音源（JS 桥接 = 洛雪/爱坤插件，HTTP 自定义源）→ 同步 UI 导入的音源配置。
3. **2. LoL 模块**：创建 LoLRuntime（内含对局提醒引擎、资源计时器）。
4. **3. 语音输出**：TTS（合成声音说话）。
5. **4. 播报队列**：SpeechQueue（排队播报）+ SpeechJudge（判断一句话该不该播，避免烦人）。
6. **5. 语音输入**：先检查/拉起 ASR 服务（llama-server，若 8080 端口没跑就自动启动，最多等 60 秒）→ 创建 VoiceRuntime。

然后 `start()` 依序启动所有模块：调度器 → 音乐 → 后台扫描音乐库 → LoL → 对局身份服务（Ongoing，ChampSelect 时加载 10 个玩家）→ TTS → 语音 → 发布"系统启动"事件。

**注意**：麦克风默认**不自动开启**，需要点状态栏的 🎤 按钮才开始监听（有意设计，避免每次启动就偷偷开麦）。

## 五、功能模块详解

### 5.1 语音控制链路（voice）——"听懂你说的话"

**功能**：说"播放周杰伦的晴天"→ 播放；说"随机播放"→ 切随机模式；说"对面石头人闪现了"→ 记冷却并语音提醒。

**实现思路**：整个链路是"识别 → 理解 → 执行"三段式，全部本地、纯规则（已移除大模型 LLM，保证快和稳）。

**执行方式**（一段语音的完整旅程）：
```
麦克风采集(pyaudio, 16kHz) 
  → 音量阈值 VAD（检测到说话才开始识别，静音不浪费）
  → llama-server ASR（语音→文字，打印 [Voice] 识别: ...）
  → 规则意图引擎 RuleBasedIntent（文字→意图）
     例：「播放周杰伦《晴天》」→ 去掉标点 → 匹配模板「播放xxx」
     → Intent(music.search_play, query=周杰伦晴天)
  → VoiceRuntime 把意图转成 Command 发到命令总线
  → 对应模块执行（音乐控制器搜索并播放）
  → 控制台打印 [PERF] 耗时统计（asr/intent/command 各多少毫秒）
```

**关键设计**：
- **忽略所有标点**：ASR 自带的逗号句号不影响匹配（"高潮模式，开"= "高潮模式开"）。
- **大量同义表达**：规则里穷举了"下一首/换一首/这首换掉/不听这首了/换首歌听……"几十种说法。
- **置信度**：精确短语匹配 0.99，带变量的模板匹配 0.90。

### 5.2 语音播报（speech）——"它会说话"

**功能**：技能冷却提醒、游戏事件语音播报、语音回复。

**执行方式**：事件 → SpeechQueue（排队，避免多条播报同时响起打架）→ TTS（edge-tts 生成 mp3）→ mpv 播放。SpeechJudge 负责判断"这条播报该不该说"（比如冷却好了才提醒，避免刷屏）。

### 5.3 音乐播放（music）——"本地 + 在线都能播"

**功能**：本地音乐库扫描、播放/暂停/上一首/下一首/随机/顺序/单曲循环、搜索播放（本地没有就转在线）、在线音源管理（可导入自定义音源）、高潮检测（"跳到高潮"）。

**本地播放执行方式**：
```
启动时后台扫描音乐库（scanner）
  → 用 mutagen 读歌曲标签（歌名/歌手/时长）存入 SQLite
  → 每首歌跑一次高光检测（highlight_detector，V4 算法找最燃段）
  → 用户双击或语音点歌 → MusicController 查库 → mpv loadfile 播放
  → 播放进度/结束状态由后台线程轮询 mpv 获得
```

**在线播放执行方式**：
```
本地没找到 → 所有已注册音源并行搜索（多线程，每源 5 条结果）
  → 优先选酷我音乐的结果（已验证可匿名播放）
  → 按音源取播放 URL → mpv 播放
```

**在线音源体系**（多轮重构后的现状）：
- **js_bridge（JS 音源桥接）**：用 Node.js 子进程跑洛雪/爱坤插件（`data/music_sources/lx/爱坤.js`），搜歌和取 URL 都走这个桥（NDJSON 协议）。酷我搜索结果实际来自这里。
- **HttpJsonSource（HTTP JSON 自定义源）**：用户在 UI「音源管理」导入的 JSON 音源（洛雪风格 `/search`、`/song/url` 接口）。失败会被分类记录（网络/超时/HTTP 状态/JSON 解析/结构不兼容），单个源失败**完全隔离**，不影响其他源。
- **demo / archive 源**：演示用，默认禁用（网络慢会拖慢搜索，配置里可开）。

**性能关键点（修过的历史问题）**：
- 曾经"播放周杰伦"要 **23.6 秒**：根因是拿到歌曲后把所有音源逐个串行问一遍 URL（demo/archive 各失败一次拖 ~16s）。修复后：按音源**定向取 URL**，整链路降到 **2.6 秒**。
- 音源搜索结果带**缓存**（带版本号，源被替换后旧结果自动作废，不会污染新源）。

**高潮检测（highlight）**：
- V4 Early-Rise 算法：读音频 → 算音量包络 → 找能量最高峰 → 从峰前 35% 上升处开始、峰后 30% 下降处结束，得到"高潮段"（15~75 秒内合法）。
- 优先用在线参考（酷我外部参考时间），无参考才本地算，实在没有就是"无高光"。
- 修复过的坑：174 首歌曲因 dict 键重复导致 171 条记录（已修）、坏文件解码器报错刷屏（已静默）、检测失败静默执行。
- 语音说"高潮模式开/播放高潮" → 自动 seek 到高潮起点。

### 5.4 LoL 辅助（lol）——"打游戏时的得力助手"

**数据来源**：全部来自英雄联盟**客户端本地接口**（LCU，端口由客户端动态分配，程序自动发现），不碰游戏内存、不注入，安全合规。

**功能与执行方式**：

1. **对局身份服务（Ongoing）**——核心数据层
   ```
   读取 LCU Gameflow（对局流程状态：选人/加载/对局中/结束）
     → 构建 CurrentGameSession（我方 5 人 + 敌方 5 人，含段位/战绩/英雄）
     → GSM 补充身份源（腾讯 GSM 接口按 puuid 查双方完整身份，
        仅对局中/加载/重连阶段启用；Gameflow 是主源，GSM 只追加 Gameflow
        完全缺失的玩家，不覆盖；GSM 失败无损降级）
     → 2999 实时数据（客户端实时事件端口）合并实况字段（金钱/击杀/装备等）
     → PlayerSnapshot 快照 → UI 面板 + Overlay 悬浮窗
   ```
2. **语音记技能（GameAlarm）**：说"对面石头人闪现了"→ 自动识别英雄+技能 → 开始 300 秒倒计时 → 冷却好了语音提醒"石头人闪现好了"。支持闪现/点燃/疾跑等召唤师技能和大招。
3. **资源计时器（ObjectiveTimer）**：自动检测小龙/大龙/峡谷先锋出生和击杀时间，到点语音提醒。开局 15 秒左右自动校准。
4. **手动技能计时（Cooldown）**：语音查询"对面瑞文闪现还有多久"→ 读静态数据表（英雄技能 CD）+ 记录手动计时。带 AxiomArc 规则引擎自动补录（根据对面交了技能等表达）。
5. **对局自动化（Automation）**：自动接受对局、自动禁用/选英雄（默认 `enabled=False` 关闭，需要用户在界面启用）。
6. **玩家情报（player）**：查询"对面亚索的段位/战绩"→ 通过 SGP 接口懒加载账号比赛历史、段位、胜率，语音播报。含经济顾问（economy_advisor，游戏内经济数据分析）。
7. **ChampSelect 数据**：选人阶段加载双方 10 人信息（隐藏了身份的玩家用 display_name 显示"敌方召唤师1"等）。

**未解决的技术疑点（诚实交代）**：历史日志曾出现"我方 5 + 敌方 4 = 9 人"但真实对局敌方是 5 人。调查结论是"证据不足，无法确定第 10 人是在哪一层消失"（可能是 Gameflow 原始数据本身、也可能是某个身份字段为空被过滤）。已接入 GSM 补充源尝试弥补，但需要真实对局进一步验证。

### 5.5 UI 与悬浮窗（ui）

- **主窗口**（PySide6）：底部 Tab 页——音乐播放面板（歌单/搜索/播放模式按钮/音源管理）、对局面板（双方 10 人卡片，显示英雄/段位/战绩/状态）、冷却面板、自动化面板。
- **状态栏**：LCU 连接状态、ASR 状态、🎤 麦克风开关。
- **Overlay 悬浮窗**：游戏内半透明悬浮窗（可拖动、跟随游戏窗口），显示对局双方信息。
- **系统托盘**：最小化到托盘。
- **语音指令 ↔ UI 同步**：语音切"随机播放"→ 界面按钮同步变成"🔀 随机"；语音开关"高潮模式"→ UI 同步。

### 5.6 录音转写（配套能力）

飞书/豆包会话内可启动录音并转写（独立于主程序，属于豆包侧能力，本报告不展开）。

## 七、已知问题与风险（截至本报告）

1. **LoL 敌方第 10 人身份**（🔴 待真实对局验证）：GSM 已接入但未在真实对局确认能补出第 5 个敌方身份。
2. **ikun 音源**（🟡 无害）：其 api_url 是从爱坤.js 提取的插件内部变量，不是可直接 GET 的 JSON API，每次搜索会"网络异常"但已静默隔离，不影响其他源。建议在 UI 禁用或改配真实 HTTP 源。
3. **语音麦克风**（🟢 已知行为）：默认关闭，需点 🎤 开启；"说话没反应"先看 🎤 是否开启。
4. **坏文件/无法播放**（🟢 已静默）：自动跳过逻辑保留，控制台不再刷报错。
5. **需要真实环境验证**：mpv 请求头跨源行为、App 退出时的线程池收尾、ASR 偶发未拉起（启动等待 60 秒逻辑）。

## 八、给 Deepseek 的快速上手提示

- 这是**单机桌面应用**，不是服务端；所有"语音"都是本地 ASR + 规则意图，没有 LLM。
- 模块间靠 **事件总线 + 命令总线**解耦：语音只负责"识别+意图→命令"，音乐/LoL 只负责"执行"，互不依赖。
- 调试入口是**控制台日志**（`[Voice]` `[Music]` `[mpv]` `[Ongoing]` 前缀），另有 `data/events/` 事件回放。
- 跑测试：`py -3.11 -m pytest tests/... -p no:cacheprovider`（当前音乐相关 83 个测试全绿）。
- 想复现任何"语音没反应"问题，用 `tools\start_voice_debug.bat` 启动（强制无缓冲输出 + 全链路时间线落盘 `data/voice_debug/`）。
