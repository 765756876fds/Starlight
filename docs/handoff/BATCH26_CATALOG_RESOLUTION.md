# 第26批 目录搜索与解析协作

本批复用星芒的分页、严格录音匹配、品质探测、下载台账、独立 MPV 和 AppContainer。依据洛雪固定提交 `323e4bac505da428adae8db6b58039fb2b36b86d` 的平台搜索结果格式与 `musicInfo` 解析契约，独立适配目录到解析器的交接。原平台网络代码和第三方音源均未进入正式仓库。

## 受控配置

沿用第25批的 `--isolated-music-config`。可在宿主维护的配置中增加可选的 `catalog_routes` 数组。每项包含已批准 MusicFree 目录的 `catalog`、一个 `platform`、按尝试顺序排列的已批准 LX `resolvers`。解析器必须在宿主配置和插件实际能力中均支持该平台。普通启动和无映射的音源维持原有路径。

目录插件应明确输出原平台 `songmid`。目录本身的 `item.id` 继续用于目录分页、结果选择和播放历史。字段包含时按受控声明保留原生辅助标识，例如 QQ 的 `songId`、`strMediaMid`、`albumMid`，咪咕的 `copyrightId`。酷狗需同时提供主 hash，并保留各品质 hash。相同 `musicInfo` 派生的两个解析候选仍然对应同一条目录记录。声明大小与品质继续等待前置探测和完整媒体校验。

目录和解析器使用独立的插件身份和授权代次。返回地址由解析器的资源策略授权，同时绑定来源目录租约。任一租约失效后，旧资源授权随之失效。续传根据原目录、目标解析器和原平台身份重新授权，还须通过第20批的字节一致性验证。下载胜出的解析器缺少附件时，可在双方租约有效期间查原目录的歌词和封面。跨录音替换继续受第18批原有严格规则约束。

## 来源门禁

洛雪上游代码及 README 附加条件需要分别审查，平台访问和媒体分发也需要各自授权。当前没有批准接入的商业搜索适配器。本机少数脚本静态声明自定义搜索，需要单独做版本、许可、签名、平台授权、分页及错误契约验证。现有受控入口仍按已批准的 `musicUrl`、歌词和封面能力运行 LX。无发布者签名的本地脚本仍停在审查阶段。

## 可复用覆盖率验收

```powershell
python -B tools/music_coverage_matrix.py observations.jsonl -o report.json
```

录入目录命中、页码、录音核对、解析、实际读取、解码、持续播放、声明与实际品质、下载前整件大小、下载及恢复证据。工具按证据类型及试验身份统计。两个解析器共享一条目录试验时，目录命中只计一次。受控夹具、授权公网实测和授权商业曲库分别记录。缺失观察保留未知状态。
