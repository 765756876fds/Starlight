# Starlight 产品维护记录

更新日期：2026-11-05。目标是少操作、真实反馈和可靠使用；本记录不是自动施工或发布授权。每轮只更新受影响条目，不把所有设想列入开发计划。

## 如何维护

- 状态分为：已实现、自动化支持、历史联网/用户验收、真实缺陷、条件性风险、待实机验证、待复现。
- 条目保留用户影响、代码/日志证据、最小下一步、依赖/风险和完成标准；修复并验证后转入已完成，不无限堆积旧任务。
- 没有新证据时不重新审计已收口能力；不把“能导入”“有数据”“离屏通过”分别夸大成联网、播放或实机成功。
- 最初建立本记录的批次仅新增规范与文档。后续修复以下各条目按实际施工更新；历史验证与当前验证分别记录。

### R4 · P2：验证并收口 LCU 鉴权失效的恢复边界

- **状态：内存替身复现的条件性风险，非当前实机故障结论。** `app/lol/lcu.py::request_raw` 在401响应后仍清零 `_fail_streak`、保持 `_connected=True`；`_reconnect_loop` 只在未连接时重新发现。受控连续两次401可重复此状态。
- 用户影响：凭据失效且 WebSocket 没先触发断连时，可能持续显示连接但请求无有效数据；其他事件仍可能先恢复，不能宣称一定永久卡死。
- 最小下一步：针对鉴权失效设计有界断连/重新发现测试，复用现有连接生命周期；同时验证404/429/5xx等暂时响应不被错误当成过期凭据。不扩大到自动化、Riot/SGP 架构或所有 HTTP 错误策略。
- 完成标准：过期凭据能够恢复发现，状态变化反馈准确，无凭据日志、重复线程或无界重试；真实客户端退出/重开另行验收。
