# 第25批 AppContainer 音源宿主

受控入口为 `python -B main.py --isolated-music-config ABSOLUTE_PATH`。显式启用后，星芒仅注册该入口配置的托管音源。这个入口不扫描默认插件目录和自定义 HTTP/Python 音源，也不连接外部洛雪播放器。默认启动仍使用第24批的既有路径。隔离启动或校验失败会停在当前托管源的不可用状态。

## 配置与批准

配置由宿主所有者单独维护。顶层字段为 `work_parent`、`trust_root`、`node`、`trust_policy`、`trust_policy_sha256`、`sources`。前四个路径必须为绝对路径。运行工作目录和信任台账应处于不同的宿主自有目录，台账不得向插件开放写入。父目录由部署者预先创建，运行目录由宿主在本地支持持久 ACL 的路径下独占创建。

`sources` 最多有四项，每项包含 `plugin`、`type`、`providers`、`policies`。MusicFree 的 `providers` 为空，LX 明确枚举允许解析的平台。授权按 `host_http`、`playback`、`download`、`cover`、`lyrics`、`metadata` 设置。每项需要准确的 origin、`timeout` 和 `body_bytes`，也可以指定允许的方法和请求头。CLI 不接受测试环回豁免。受控验证通过程序内明确的测试主体与确切 origin 授权环回测试服务。

第24批 `PluginTrustStore` 继续处理候选、验证、审查、用户授权、启用及撤销。每个来源必须对应可信策略中的明确插件身份，配置来源共用一个已批准 Node 指纹。启动使用签名清单的确切文件字节和冻结的宿主代码，复核运行时的实际文件句柄后启动 Windows AppContainer。代码目录和运行时只有读/执行 ACL，只有该实例的工作目录授予修改权。

## 运行与排障

最多四个插件进程，每个插件最多三个已受理业务调用。信任变化时退休原实例租约，旧授权不进入重启实例。每来源独立检查信任台账。台账由其他进程写入时，撤销传播还受 SQLite 可读时间和轮询周期影响。应用内始终使用最新实例租约发出新的受控网络请求。

会话不受理任意包依赖，支持声明的相对 JS 和 JSON。搜索结果携带稳定身份，原始 URL 只保留在所属实例的短期缓存中。只带 `item.url` 的来源在重启或缓存淘汰后要重新搜索。LX 作为明确平台的资源解析器接入，独立搜索、榜单与浏览未纳入本入口。

独立 MPV、前置探测、下载和附件网络请求继续走第24批的受控传输。下载台账保留恢复所需的来源、资源标识和媒体一致性证据。恢复时重新解析并建立授权。暂停中的在线播放保留当前来源实例，显式撤销仍会停止旧授权下的请求。同步 DNS 调用如晚于 HTTP 取消结束，仍计入实际占用。

实机复验使用项目外源码副本、独立配置、独立 IPC 与受控合成媒体。启动参数仅选择音源宿主，应用数据隔离仍由验收环境配置。真实第三方插件、默认替换、打包部署须分别验收，当前保持受控入口用途。
