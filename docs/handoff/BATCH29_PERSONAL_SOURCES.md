# 第29批 个人音源

## 普通入口

「发现音乐」没有在线目录时，点击「打开音源设置」，再选择「个人音源」。可导入本地 JSON 或本人有权访问的 HTTP(S) 配置链接。勾选、取消勾选、删除用于管理该配置。配置中的服务基础地址只显示主机名，界面上的“已启用”表示已接入搜索。曲目、可取得的资源及实际音质以本次使用结果为准。

最小配置包含 `name` 和 `api_url`，可选 `search_path`（默认 `/search`）、`song_url_path`（默认 `/song/url`）和布尔值 `enabled`（默认启用）。应使用现有 HTTP JSON 协议，例如搜索响应 `{"data":[{"id":"1","title":"曲名","artist":"作者"}]}`，歌曲地址响应 `{"url":"https://your-service.example/audio.mp3"}`。通用 HTTP JSON 适配器只提供单页搜索和服务返回的默认资源。具体音质仍由媒体确认，文件下载仍受下载传输策略和实际校验约束。只有元信息的旧配置不会被删除或另行解释。

普通入口继续支持已配置的旧宿主，设置仅显示当前已加载的 MusicFree／洛雪插件及宿主识别的角色。旧插件的搜索检查仅用于确认能否搜索及取得地址。本地 JS 导入和直接更新入口已收口，新增或更新 JS 从既有审查和受控启动路径处理。

## 受控入口

用已有受信配置以 `python -B main.py --isolated-music-config <已批准的启动配置路径>` 启动。「设置 → 音乐 → 查看受控音源」展示插件角色、批准版本、审批或撤销状态、目录到解析器的路由及配置允许的媒体用途。「刷新状态」只读本地审批记录。审批状态不能保证某首曲目有资源。

插件包加入、批准、撤销、版本更换和配置维护仍沿用第24至26批的宿主及信任工具。UI 不创建审批或扩大网络权限。MusicFree 原生 ID 与该平台的 LX 解析按既有映射和授权传递，由音频解码及完整媒体校验给出实际音质证据。具备自有或获授权服务的场景，优先复用通用 HTTP JSON 或批准目录和解析器组合。正式工程没有新增 OpenSubsonic、Jamendo、网易云原生适配，也没有扩大商业曲库覆盖。

本批触及受控宿主的只读审批概览，受控进程、AppContainer、MPV 归属和回收逻辑沿用第27批。若调整上述生命周期路径，应继续通过实机异常回收验证。
