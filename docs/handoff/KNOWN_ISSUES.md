# Starlight 已知问题（重装前收口）

只记录当前仍会影响实际使用、恢复或交接的事项；历史一次性问题不再重复展开。

## 音乐

1. 搜索自动重排：当前实现可能在每个增量页重排；产品要求是首批快速展示，后台比较资源后**只自动重新排序一次**。
2. 音质标识与选择：搜索/下载界面仍需统一为 MP3、FLAC、Hi-Res 等通俗标识；不显示文件大小或模糊的“高档/超高档”。
3. 下载默认值：应默认选择实际可用音质及对应大小；播放品质与下载品质独立，不能用一个档位代替另一个。
4. 同录音合并：同一录音版本合并、不同版本保留的边界仍需真实曲目复核，避免误合并或错误替换。
5. 设置体验：音乐设置页需要整理，滚动失效等实际使用问题要修。
6. 歌词：保留现有沉浸歌词；后续增加逐字跳动，并让“文字特效”按钮显示当前特效名称。
7. 音源：精而互补，不追求数量；保留本地文件、网络链接添加及可靠更新/回退。

## 影视

1. 最高优先级是搜索正确、能够播放、持续流畅；清晰度可以适当妥协，不为 4K 牺牲稳定性。
2. 部分资源可能失效或需要重新授权；换源必须以内容/时间轴身份验证，不能只看“加载成功”。
3. 先测试现有资源和其他成熟方案，再确定功能标准；没有稳定观看方案时不盲目扩大研发投入。

## 游戏、语音、高级视觉

- 游戏助手参考 Akari 等成熟软件，够用即可；不为“完整”扩大权限或改系统安全策略。
- 语音以方便日常使用为主；复杂技能编排不是当前重点。
- 高级科幻视觉在音乐、影视、语音等基础业务稳定后再推进。

## 工程与恢复

- Lite/Full 构建路径仍有 `dist\staging` 与 `dist\Starlight` 不统一；仍依赖 LM Studio 的 `llama-server.exe` 复制。干净 Windows 恢复优先用私人备份中的 `third_party/llama`。
- `package-lock.json` 已评估可跟踪；若 `npm ci` 因 lock/package 不一致失败，再用 `npm install`，不要把旧 `node_modules` 直接复制到新机。
- B5 遗留 `test_voice_adversarial` 历史失败只作私人研究留档，不扩大修复范围。
- Qt 原生堆 P1 尚无稳定最小复现；未定位前不宣称修复。
- 旧安装目录不完整，不能作为回滚基线；源码版和安装版数据库不要同时写。
