## 普通进度条上的副歌

- 酷我需要插件把搜索响应中的 `payInfo.refrain_start/end`（毫秒）与歌曲 RID 保留下来，并为实际取址提供同录音证据。GitHub 提供消费契约和模拟测试；本机增强的 `kw.js` 受忽略规则保护，更新插件可能丢失映射。可用测试核对 RID、两个边界、实际整曲时长和下一首清除，避免整文件覆盖。
- 汽水可在同一次取址已有响应中核对歌曲、VID、完整可播放范围及最终媒体。只有起点时只画一个点。隔离协议验证通过，真实整曲覆盖率待测。
- 网易云歌曲 ID 和酷狗实际媒体 Hash 可进入适配器测试；额外查询默认未启用。授权和长期稳定性未确定。QQ 缺少经验证的同版本副歌证据。单凭同名、试听起止或音量峰值均不足以画平台标记。
- 手动高潮记录和本地高潮模式继续独立；播放条标记由用户点击跳转。各平台只统计真实起播后的可见标记，搜索结果里有字段不代表能显示。

## 后续体验优先级

| 次序 | 可验证的小步改进 | 收益 / 难度 / 风险 |
| --- | --- | --- |
| 1 | 在线音乐起播失败时，让现有反馈直接指出可以重试还是返回已保留的候选；用失效地址和未知回执验证不会重复加载 | 高 / 低至中 / 低 |
| 2 | ASR 慢时测量并缩短音乐、电影已经就绪后的额外等待；须同时证明加载中退出不会再次创建进程 | 高 / 中 / 中 |
| 3 | 锁定歌词窗口旧断言所对应的用户动作，先验证切歌、关闭、重开和迟到歌词，再决定修哪一层 | 中高 / 中 / 中 |
| 4 | 在已有电影续播和失败返回入口上，减少找回上次影片、集数和来源的操作。用同名不同版本验证不会跳错进度 | 中 / 低至中 / 低 |
| 5 | 对 LoL 缺席时的空闲轮询取样，有实际负担再加退避，同时测游戏启动后首次提醒延迟 | 待实测 / 低至中 / 低至中 |

暂缓全仓拆分控制器、跨 CMS 自动进度映射、重做播放器及训练副歌模型。现有受控换源证据覆盖范围窄；在音乐与电影之间共享播放权或在多个系统之间共享时间轴前，先取得同录音、同集数和请求代次证据。
