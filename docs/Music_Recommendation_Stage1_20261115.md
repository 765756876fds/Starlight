# 音乐本地记忆与推荐：第一阶段

## 使用

- 在在线音乐发现页点击“为我播放”，或说“我想听歌了”“放点歌听听”“放点我喜欢的”。
- “来点伤感的”支持伤感、轻松、摇滚、怀旧、动感五类榜单名称/分类粗粒度匹配。没有匹配资料时明确失败，不把普通热榜冒充伤感歌曲。
- “换一个”仅在真实当前音乐属于推荐集合、且电影没有播放时，消费现有队列下一首。“换个榜单”才重新选榜。
- “换个风格”排除当前榜；当前风格未知时如实说明仅更换榜单。没有可用替代时反馈失败。
- “喜欢这位歌手”保存明确歌手偏好；“减少这首”让下次选歌避开该来源的具体歌曲版本。不会删除文件、收藏或歌单，也不立刻移除当前队列。
- 明确点歌、已有榜单序号和手动歌单走原链路，不经过推荐。

## 存储与隐私

偏好库 `music_preferences.db` 位于当前配置的音乐数据库同目录。源码默认 `data/`，安装版默认用户数据目录的 `data/`；不会修改原音乐数据库结构。库文件只在首次使用/记录时创建，短连接串行访问，不增加常驻线程。

schema v1：`behaviors` 存有限行为（最多2000条）；`preferences` 存明确偏好；`catalog_cache` 存榜单名称/来源缓存；`memory_meta` 存幂等导入标记。表保留 domain 字段，当前只写 music。

首次推荐只读导入最多100条旧历史，作为弱种子；只导入一次。自动推荐和自动续播的记录不参与偏好推测；手动收听按歌曲/日期去重并封顶，普通下一首不记为负面偏好。不会记录原始录音、账号凭据、播放URL或整份插件原始对象到偏好库。

同名歌曲不会跨平台盲目合并：来源、来源ID、标题、歌手、专辑、时长共同参与保守身份匹配。不同版本可能分别保留，这比错误合并更安全。

初始化幂等；遇到损坏、不可写或未来版本的偏好库时保留原文件并降级为无记忆选歌，仍保留原历史/歌单。明确反馈保存失败。修复权限/文件后重启可重新尝试。

## 策略及边界

1. 本次明确风格硬筛选；其次明确偏好，再看主动历史，最后按榜单排名加权随机。榜单标题只能提供粗粒度标签，不能证明歌曲实际情绪。
2. 原始平台热度不跨平台比较。同一匹配层按排名位置加权抽样，不永远固定第一首。高优先级候选失败后才尝试较低层备用项。
3. 仅复用当前注册的榜单接口；最多读取3个榜单的第一页，每页最多保留50首、前20首参与起始选曲，最多4个不同歌曲候选。尽量先覆盖不同来源。
4. 年代/语言只使用插件明确提供的 `year` / `language`。没有数据就不参与推断；没有新增音频分析、搜索引擎或云端推理。
5. 网络使用现有 OnlineSourceManager 线程池及桥接超时，单次读取等待最多20秒，总推荐预算45秒；取消检查间隔最多约100毫秒。已经运行的只读插件任务不能强杀，仍由原桥接超时收尾；没有创建第二套常驻任务池。
6. 旧语音、手动播放、停止、关闭和音源注册代次变化会使旧推荐失效，紧贴 MPV loadfile 前再次校验。IPC 接受与实际起播分开：只有路径、播放位置和非空闲状态确认后才显示正在播放；无法确认则显示待确认，不宣称成功。
7. 起播成功后，当前榜单旋转为“所选歌曲 → 后续歌曲 → 原榜单前段”的一个现有队列集合。顺序、随机、单曲循环及E→D插队规则继续由原队列处理；普通下一首/自然接续不重新获取推荐。集合耗尽遵循原队列停止规则，可再次要求推荐。
8. 新推荐替换当前临时播放集合，与现有在线歌单播放一致；不会删除用户保存的歌单或历史。没有可解析URL时不替换原队列。
9. 界面使用现有双主题控件、LatestTask和排队信号；语音结果同时回传音乐页及通知中心，不依赖TTS成功，也不重复执行业务。

## 验证证据

基线6条核心语句未进入推荐；新实现进入推荐命令。定向测试覆盖偏好持久化、幂等/未来版本/损坏降级、推测隔离、排序与随机、有限失败备用、取消和超时恢复、手动播放保护、语音安全、真实控制器队列消费及Qt关闭。

真实 MPV 验证使用生成的静音音频、隔离命名管道、无用户配置和空音频输出，覆盖 VoiceRuntime → CommandBus → 控制器 → loadfile → 自然EOF接续的顺序、随机、单曲循环。它证明真实解码与接续，不代表真实网络歌曲或麦克风/扬声器实机验收。

2026-11-15有限真实联网抽查：开心汽水返回4个榜单目录；热歌榜详情未取得歌曲，插件报 `track_ranks` 字段访问异常。酷狗、酷我、腾讯、网易、溯音网易、酷我(念心音源)目录请求超时。因此当前网络抽查没有确认可在线播放的真实榜单歌曲，也没有可统计的年代/语言覆盖率。未修改网络配置，不虚构数据补齐。

精确测试统计、提交及Windows Unit/UI CI结果以本轮维护记录及对应SHA的CI为准。源码功能不会自动进入此前的旧安装包；本轮没有打包。
