# 影视推荐与跨媒体情境控制：第二阶段（2026-11-15）

## 用户流程

- “我想看电影了”“我想看电视剧”“我想看动漫”准备最多6个公开榜单候选，切到电影页展示；不会自动播放。
- “给我找几部高分悬疑电影”“来点科幻电影”使用有限、明确的类型词。高分指已有来源提供的十分制评分至少8分；缺少标签或评分的条目不能充当匹配结果。
- 单击候选看详情，双击仍使用已有多源片名搜索，选择片源后沿原视频窗口入口播放。榜单来源、评分来源和播放来源保持独立。
- “继续看上次的电视剧／动漫／电影”：只有一个可靠进度记录时沿原窗口入口恢复；多条记录展示供选择。旧历史缺少分类或进度时仅展示，不自动决定。
- 首页增加“为我推荐”“继续上次剧集”“换一批”；详情增加“喜欢这部”“不感兴趣”。保留电影、电视剧、动漫、综艺、发现、本地影片六个导航。
- “先停一下”“停一会儿”“接着放”读取真实MPV状态。没有可靠对象就不执行；音乐播放集合明确时“换一个”消费已有队列，不重新选榜。
- 电影场景的“换一个”不猜测换片还是跳集，提示用户明确“下一集”或推荐电影。明确点歌、明确电影名和原“暂停”全局暂停契约保留；“继续”优先恢复原全局暂停的有效代次，否则按当前可靠暂停状态判断。

## 本地记忆与隐私

独立 `movie_preferences.db` 位于原 `movie_history.db` 同目录，不更改音乐偏好库、music.db和旧movie_history表结构。schema v1按需幂等初始化，未来版本、损坏、不可写时保留原文件并降级。连接在事务结束后立即关闭，SQLite忙等上限150ms。

- `preferences`：用户明确设置的内容/类型/地区/年代/来源偏好。
- `feedback`：明确喜欢或不感兴趣的作品及可信元数据。喜欢一部作品只将该作品记为明确偏好；从其类型、地区推测的偏好仍标为推测。
- `viewing`：最近最多500条已知分类的实际观看记录、进度、时长、集数及最小重放字段。观看达到30秒，或短内容达到80%，才影响推测；95%或实际EOF视为完成。中途关闭不产生负面偏好。
- `actions`：最近最多200条主动搜索/选择行为。它们不自动成为喜欢，也不记录完整语音或录音。
- 喜好反馈用一个事务同时写内容偏好和反馈；失败整体回滚。推荐使用一次只读事务快照，避免多次建连和混合读取不同时刻的状态。
- 本地重放字段保留原有已选片源URL/路径和分集列表，以供恢复；不会复制请求头、Cookie、凭据或整份接口原始响应。私有数据库与历史均不提交Git、不进入本轮产物。

只使用真实存在的地区、年份、标签；本地影片分类不明时继续沿旧历史与MPV watch_later续播，不凭文件时长猜类型。可识别的本地SxxEyy剧集复用已有文件名索引信息。

## 策略、数据与来源

明确类型先筛选；明确内容和属性偏好高于历史/喜欢作品衍生的推测。在适合的层级中，按榜单名次加权随机；不跨平台比较原始热度。可确认的未看作品优先，正在观看的已确认作品放回继续观看；已看作品降级。不同年份、季数或来源不明的同名作品不强行认作同一部。

复用 MovieDiscovery 的B站、爱奇艺、腾讯公开榜单和原有超时、缓存、部分成功机制；优酷、芒果TV仍沿原官方入口。B站真实的“7.3分”评分文本或结构化score可规范化。分类检索复用已有豆瓣信息客户端，返回的分类标签与分数标明来源；不创建新的影视客户端或播放解析器。

本轮有限只读联网：
- 电视剧：B站100、腾讯50、爱奇艺25，共175条，三个来源成功；65条含可用评分，0条包含已接入的类型标签，0条年份。真实数据经过推荐器得到6条候选。
- 电影：本次三个来源均超时，0条候选，正确反馈失败并保留本地/续播能力。
- 另一次B站电视剧原始字段抽查100条，确认rating为“7.3分”一类文本。豆瓣悬疑分类本次返回0条；原客户端不能进一步区分空结果与服务不可用，未伪称成功。
- 本轮不能宣称真实平台“高分悬疑电影”已联网验收；严格筛选的正确性用明确标记的测试数据验证。没有标签的平台不会靠片名猜悬疑或科幻。

候选信息不等于可播放地址；本轮不自动取得或播放未选择的影视片源。公开榜单没有分页时仍取原接口整页；UI与推荐仅使用有限候选，不宣称减少了服务器响应。

## 情境与异步安全

MediaContext在现有命令线程中读取两边的运行、空闲、暂停和媒体路径，结合控制器代次判断；执行前复核两边快照。GUI事件过滤器只提供焦点/最近操作提示，不在工作线程访问Qt控件。两个播放器活跃且无可靠依据时才提示明确对象。已确认暂停记录有时限且绑定媒体路径和代次，不使用上一句语音代替播放状态。

推荐代次、语音请求代次、LatestTask序号和Qt排队信号共同隔离旧结果。切换分类、离开电影页、手动搜索/播放、停止或关闭使旧结果失效。延后到GUI执行的续播和实际loadfile前也有守卫。语音明确电影搜索沿原play参数契约，通过线程局部守卫与新推荐协调，不改变手动调用的条目对象身份。

电视剧/动漫保存当前集与最小分集列表；实际EOF有下一集时保留下一集起点，不把整部剧当作已看完。恢复在线进度用原MPV seek，限定确认次数并绑定集数和代次；本地影片继续依靠原生watch_later。不因播报失败重放业务。

没有新模型、运行依赖、常驻线程或定时任务。网络沿既有有界请求、MovieDiscovery并发和CommandBus/LatestTask执行；不改ASR、TTS、MPV或LoL架构，不修改网络设置。
