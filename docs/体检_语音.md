## ① 现有功能

### ASR 语音识别
- **Qwen3ServerASR（主）**：llama-server HTTP API（`/audio/transcriptions`），模型常驻、延迟低
- **Qwen3ASR（备）**：llama-cpp-python 本地加载（多模态 audio_url），llama-cpp-python 未装时不可用
- 启动拉起 llama-server，等待 `/models` 200（最多 60s，503 时 2s 重试）；转写路径单次探测不阻塞

### 意图路由（纯规则，无 LLM）
- RuleBasedIntent：正则规则引擎，**确定性**，覆盖：音乐控制 / 游戏提醒 / 冷却计时 / 玩家查询 / 搜索播放
- IntentRouter：命中返回 Intent，未命中返回 `system.unknown`（不产生副作用）
- **写操作要求明确动词**（"记一下/用了/插了/提醒我"），裸陈述不触发（防误判设计）

### TTS 播报
- **TTSController**：Edge TTS（在线）→ 临时 mp3 → 独立 mpv 进程播放；状态机 IDLE→GENERATING→PLAYING；403 重试 3 次（0s/1s/3s）+ 失败清理残留文件；可停止/可追踪/不阻塞
- **SpeechJudge**：事件→等级（S/A/B/C/DROP），"信息可以丰富，语音必须克制"——绝大多数即时事件 DROP（龙/先锋/一血/多杀/团灭全部静音），只有 ALARM_TRIGGERED 允许 B 级即时播报；min_interval 5s 防连播
- **SpeechQueue**：优先级 S>A>B + 同优先 FIFO + 高优先级打断 + event_id 去重 + TTL 过期 + 上限 10 条

### 麦克风
- 状态栏按钮开关（toggle_mic），**默认关闭**（`_mic_on=False`），开麦后持续监听（免唤醒）
- VAD：音量阈值 500（RMS）、静音 30 帧（~0.7s）判句尾、最短语音 5 帧

## ② 实现方式

### 数据源 / 依赖
| 组件 | 依赖 | 说明 |
|---|---|---|
| ASR | llama-server 本地服务（HTTP 8080）+ Qwen3-ASR 模型（本地 GGUF） | 全离线，不出网 |
| TTS | Edge TTS 在线接口 + mpv.exe（本地） | **在线依赖**：断网/403 时播报失败（有重试+降级） |
| 意图 | 纯本地正则 | 无外部依赖 |
| 麦克风 | pyaudio | 本地 |

### 触发链
```
[麦克风开] → pyaudio 采集 16kHz PCM → VAD（RMS 阈值分段）
  → 句尾（0.7s 静音）→ ASR transcribe → 文本
  → 标点清理 + 确定性归一化 → RuleBasedIntent.match
  → 命中 Intent → CommandBus / EventBus 执行
  → 事件 → SpeechJudge 评等级 → SpeechQueue 入队 → TTS 播报
```

## ★ 用户点名 3 项重点

### 1️⃣ 误触发率高不高？——**会误触发，无保护层**

| 场景 | 结果 |
|---|---|
| 你跟队友说"下一首" | **100% 误触发**——`^(下一首|…)$` 精确锚定，三个字裸命中 MUSIC_NEXT，无任何上下文/置信度门槛 |
| 跟队友说"暂停一下" | 同样裸命中 |
| 说"换一首吧" | ⚠️ 不命中（"吧"未在规则内）——反而躲过一劫 |
| 游戏聊天提到"闪现" | 不触发（需"记一下"动词，安全） |

**结论：高。** 音乐短指令（≤4 字）全部无保护：开麦状态下任何环境音被 ASR 识别成这几个字就执行。游戏提醒/冷却/玩家查询类因为有动词/长句要求，误触发风险低。

### 2️⃣ 有没有唤醒词？——**没有，纯免唤醒**

- 现状：麦克风开 = 持续监听，VAD 分段后**直接进规则**。无唤醒词、无"需要先说豆包豆包"
- 优点：零等待，说即执行
- 代价：**没有任何一道闸拦住环境误判**——这是误触发问题的根

### 3️⃣ "说错一个字就不认"的脆弱点——**存在，分两类**

| 脆弱点 | 例 | 影响 |
|---|---|---|
| 句尾语气词未清 | "下一首**啊**""暂停**呗**" | ❌ 不命中（标点清了，语气词没清）——用户口语必带 |
| 短指令精确锚定 | `^(下一首)$` 加 `^$` 锚 | 多一个字少一个字全不认；靠 20+ 同义词硬堆补救 |
| 长正则脆弱 | cooldown 的 CD 查询正则有 40+ 候选项串在一起 | 一个词序变化就漏 |
| 英雄名依赖 | "石头人 R 了" 中英雄名是 `(.+?)` 非贪婪 | "对面那个石头人 R 了"可能把"对面那个"吞进英雄名 |

**好消息**：搜索播放（"播放XX"）和玩家查询（子串包含）容忍度高，这两块不容易脆。

### ✅ 免唤醒要不要优化？——**要，但要分级，不是一刀切**

**判断**：免唤醒是正确方向（游戏场景说即执行，唤醒词会打断节奏）；问题不在"免唤醒"本身，在**没有任何误触发防护**。优化方案按性价比排序：

- 🟢 **A 级（必做，工作量小）**：**对局外静默**——音乐短指令（下一首/暂停/切歌等）只在**音乐面板显示/正在播放音乐**时才执行？不，更简单：**短指令全局执行但加"2 秒冷却"防连击** + **句尾语气词清理**（规则前 strip 啊/呢/呀/哦/吧/哈——一下解决"下一首啊"不认）
- 🟢 **B 级（高价值）**：**对局中才响应游戏指令**——cooldown/alarm/player 查询类规则加"当前在对局中"前置门（现在对局外说"闪现CD多久"也会触发查询空结果）；顺带解决"队友聊天聊到技能"的误触发面
- 🟡 **C 级（可选）**：**可选唤醒词开关**（设置页加"免唤醒/唤醒词"切换，唤醒词默认"豆包"）——给误触发敏感用户一条退路
- 🟡 **D 级（远期）**：ASR 置信度接入（llama-server 返回置信度，<阈值不执行）+ 语义上下文（上一句是队友话题则抑制）

## ③ 对标（主流语音助手）

| 能力 | 小爱/天猫精灵/手机助手 | 本项目 | 差距 |
|---|---|---|---|
| 唤醒 | 唤醒词（"小爱同学"） | ❌ 无（纯免唤醒） | 无唤醒 = 便捷但误触发无闸门 |
| 误触发抑制 | 唤醒词 + 本地语义过滤 + 上下文 | ❌ 无 | **最大差距** |
| 指令覆盖 | 全能（天气/闹钟/家居） | 音乐/LoL 对局垂直场景 | 定位不同，垂直场景本项目更专 |
| 识别 | 云端大模型（准） | 本地 Qwen3（离线，延迟低） | 离线是优势（游戏场景隐私+不卡网） |
| 播报克制 | 普通 | **SpeechJudge 等级克制（大量 DROP）** | **本项目独有且强** |
| 口语容忍 | 高（语义理解） | 低（精确正则，靠同义词堆） | 差在"说错字不认" |
| 垂直整合 | 无 | 语音→连招/CD/装备/对局情报 | **差异化核心** |

## ④ 增补候选

| 候选 | 标注 | 说明 |
|---|---|---|
| **句尾语气词清理**（规则前 strip 啊/呢/呀/哦/吧） | 🟢 好用且能做 | 一行正则，解决"下一首啊"不认，收益立竿见影 |
| **音乐短指令 2 秒冷却防连击** | 🟢 好用且能做 | 防"下一首下一首下一首"环境连触发 |
| **对局中才响应游戏指令**（cooldown/alarm/player 加对局门） | 🟢 好用且能做 | 解决"队友聊技能误触发"主要面 |
| **可选唤醒词开关**（免唤醒/唤醒词二选一） | 🟡 能做但工作量大 | 需改动 runtime 监听逻辑 + 设置页 + 状态机；给误触发敏感用户退路 |
| **ASR 置信度门槛** | 🟡 能做但工作量大 | 需确认 llama-server 返回置信度字段；低置信度不执行 |
| **语音回声确认**（执行后播"好的"） | ⚪ 花架子 | 与"语音必须克制"原则冲突，违背 SpeechJudge 设计 |
| **说话人分离（判断是不是我）** | 🔴 做不了 | 需声纹模型/多麦克风，超范围 |
| **LLM 语义意图** | 🔴 不做（明确设计决策） | 纯规则确定性是红线（见 intent.py 头注释：AI 不参与意图识别） |

## 附：已知缺陷与待核实
- **VAD 参数硬编码**（silence_threshold=500 / max_silence=30 / min_speech=5 在 runtime.py 内，不进 settings.yaml）——不同麦克风灵敏度差异大，用户没法调
- **ASR 超时 30s**：长句/卡顿会阻塞转写线程（有 PERF 日志可观察）
- **TTS 在线依赖**：断网 → 播报静默失败（重试 3 次后放弃）；有 `FAILED` 状态但 UI 无提示
- 待核实：llama-server 的 `/audio/transcriptions` 是否返回 confidence 字段（决定 D 级方案可行性）

## 建议优先做（若采纳）
1. **句尾语气词清理 + 短指令冷却**（🟢🟢）——两行代码量，直接缓解"说错字不认"+"连触发"两个最痛的点
2. **对局门**（🟢）——游戏指令只在对局中响应，砍掉最大误触发面
3. **可选唤醒词**（🟡）——留给误触发敏感用户，配合免唤醒默认保留便捷
