## 2. 音乐：发现、版本与队列

### 用户入口

原“在线”子页整合为“发现音乐”：原搜索框保留，增加音源可用能力驱动的分类歌单，并提供排行榜、最近播放、我的歌单的就近入口。不增加主 TAB，也不复制歌单/队列数据库。

- 插件导出推荐分类、推荐歌单、歌单详情时才展示对应入口；不支持时说明可用的搜索和排行路径，不展示假数据。
- 插件刷新后可重读当前发现页；普通歌曲搜索不会顺带重新请求推荐分类。
- 歌单曲目复用原搜索结果、播放、加入歌单和队列菜单。歌曲名称、歌手、专辑与插件来源保留，现场版等版本不按同名合并。
- 新歌/热歌等榜单由插件真实返回，不给所有音源伪造统一分类。歌手/专辑详情的能力元数据已能识别，本批没有新增完整的歌手、专辑浏览页面。
- 不自动调用插件空分类的个性化推荐路径，避免使用插件内不透明的默认账号字段；也没有下载或替换插件。

### 请求与错误

- `LatestTask` 只运行一个后台读取，最多保留最后一个待办；Qt 排队信号将完成结果投回 GUI。代次保护忽略旧结果，不撤回已发出的 HTTP。
- 真实 Qt 测试复现：榜单 A 慢请求后用户选择 B、C，旧 A 仍会更新列表和语音候选。修正为代次检查，并在 `QThread.finished` 后启动 C；原探针由 1 failed 转为 1 passed。
- 真实 Node 探针中，旧串行聚合超过 23 秒未返回。现在榜单按插件分别读取，每个最多等待 8 秒，保留可用来源和各来源错误；不改搜索、音频 URL 解析或 MPV。
- 歌单读取沿已有 Python→Node 生产链路，15 秒等待超时后可重试，不阻塞 GUI；失败不能当作正常空歌单。

### 队列拖动

播放队列原窗口中，拖动“其他队列歌曲”里的普通待播项即可调整顺序。

- 每次入队生成稳定条目标识，相同歌曲重复入队仍能精确区分。拖放携带条目标识与结构代次，不按显示行号盲目修改。
- 当前项、已播区和明确指定的下一首受保护。连续指定 D、E 仍先 E 后 D，再按原模式继续。
- 随机模式明确禁用拖动并说明原因；查看队列和无效拖放都不推进随机游标、不消耗插队状态。
- 顺序、列表循环可按调整后的待播顺序消费；单曲循环自然结束仍重复当前曲目，明确下一首优先及手动下一首规则保持原样。
- 控制器返回真实结果后更新窗口和通知，不调用播放器、不重启当前歌曲，不移动、删除文件或修改歌单。

## 3. 电影：首页、本地库与榜单

- 现有电影 TAB 默认进入“继续观看 / 我的电影库 / 热门影视”同页滚动首页。添加一次影片文件夹即可建立文件名索引，不复制影片；最近添加与全库筛选复用同一索引。
